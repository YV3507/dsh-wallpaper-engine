# ADR-0002: 设置的唯一真源收进一个共享文件，两端派生（Settings single source of truth）

- **Date**: 2026-09-30
- **Status**: Accepted
- **Deciders**: YV3507

> 实现与逐键语义在 `lib/settings-schema.js` 的文件头与各键注释里；本文只记**为什么**。

## Context

插件有宿主半（`lib/`，Node，随包发布）与浏览器半（`src/`，被构建期压平进 bundle）两侧。
设置需要**两侧都知道**：

- 客户端要**校验**用户的输入、要有**默认值**才能渲染面板；
- 宿主也要**校验**同一批键，因为它才是落盘（`~/.dsh-wallpaper-engine/config.json`）的那一侧。

两侧都要，于是最初的形态是**每一侧各抄一份表**：客户端的 `DEFAULTS`、客户端自己的
`sanitizeSettings`、客户端的 `serializeSelection`、宿主的 `sanitizeSettings`，另有宿主侧若干张
手抄枚举表。

这个形态的失效模式很隐蔽：两侧是**白名单**式的。任一侧漏掉一个键 ⇒ 该键在经过那一侧时被
**静默丢弃** —— 用户的症状是"改了没生效，重启回默认值"。没有异常、没有日志，只有"设置不听话"。
这类漂移在实际维护中发生过（见 `CHANGELOG` 中"设置改了不生效"类的修复记录），
根因永远是**同一份真源有两份手抄副本**。

## Decision

**采用单一真源文件 + 两端派生**：键集、默认值、校验规则、枚举表全部只在一个文件里定义，
该文件**同时**被宿主 `import`、被构建期内联进浏览器 bundle。两侧的 sanitize 都从它**派生**，
不再各写一份。

配套决定：

- **D1 —— 真源文件必须浏览器安全**：因为它要被内联进 bundle，所以不得出现
  `import` / `require` / Node API / 顶层副作用。这不是风格要求，是构建期硬断言的对象。
- **D2 —— 两份数据分工写在文件内**：默认值（含"只做默认值、不持久化"的那类）与
  校验规则分开表达；枚举白名单也收进来，消灭"客户端与宿主各抄一份枚举"。
- **D3 —— 两侧的差异必须显式声明**，不许靠"另一侧没有这段代码"隐式表达。
  已知差异（只存本地的键、非对象输入时两侧的不同返回）在文件里逐条写明。
- **D4 —— 两个消费者共用一个校验实现**，而不是"两侧各写一遍但期望结果一致"。
- **D5 —— 真源同时是文档的真源**：常青文档**不抄写**默认值与取值范围，只指向本文件
  （理由见 `docs/adr/README.md` §不写数值 —— 抄一份就是多一个无人复算的副本）。

## Consequences

**收益**

- **"改了不生效"这一类 bug 在结构上被消掉**：不再存在"漏登记一个键"的可能，
  因为键只登记一次。
- 客户端与宿主的行为差异从"隐性漂移"变成"文件里显式列出的若干条"。
- 面板可以直接**按真源渲染**，而不是维护一张与真源平行的 UI 表。
- 文档不再需要复述数值（D5），因此也不会腐化。

**代价（我们放弃了什么）**

- **这个文件被两侧的约束同时绑定**：它必须浏览器安全（受 ADR-0003 的 D1 约束），
  不能图方便用 `node:*`，哪怕宿主侧用得上。
- **它是构建期内联的成员**，因此必须出现在构建清单里并带标记 —— 漏登记不会报错，
  只是这个文件永远不进产物（见 ADR-0003 的代价一节）。
- **它成了热点文件**：任何一侧加一个设置键都要动它，冲突面集中。

## 重新考虑的触发线

- 出现**第二个**必须被两侧共用的内核（当前共享内核是显式白名单，见 `docs/CODE-STRUCTURE.md`）：
  届时应先决定"共享是不是常态"，而不是顺手再加一个。
- 设置规模增长到单文件难以导航时：应拆**目录**而不是拆成两侧各一份。
