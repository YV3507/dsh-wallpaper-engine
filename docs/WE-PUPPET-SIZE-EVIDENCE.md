# WE puppet 尺寸语义 — 离线实证 (第一手, 2026-02)

本文只记录**可复现的离线实测证据**，不写推测。脚本：`scripts/tmp-tex-size.mjs` /
`scripts/tmp-uv-affine.mjs` / `scripts/tmp-mdl-uvscan.mjs` / `scripts/tmp-tex-resolve.mjs`。

## 一、`size` = 真实纹理尺寸 (逐位相等)

从 `scene.pkg` 的 `materials/<name>.tex` 解出真实纹素尺寸，与场景对象的 `size` 对比：

| 壁纸 | 组件 | `size` | `materials/*.tex` | 相等 |
|---|---|---|---|---|
| 3640755971 皓风琦 | N | 3334x2501 | `materials/N.tex` = 3334x2501 | ✓ |
| 3640755971 皓风琦 | nv | 2568x2027 | `materials/nv.tex` = 2568x2027 | ✓ |
| 3640755971 皓风琦 | 十字架 | 165x366 | `materials/十字架.tex` = 165x366 | ✓ |
| 3629379075 Mutsumi | 上半身 | 1100x1106 | (同族) | ✓ |

结论：`size` **不是** "puppet 画布要铺满的目标尺寸"，而是该组件所用纹理的像素尺寸。
因此 "把网格拉伸到 size" 的实现在语义上就是错的 —— 与实测 (整体放大/出屏) 一致。

## 二、平面网格的官方恒等式 (Mutsumi 精确成立)

对 3629379075 的每个 puppet，逐轴最小二乘拟合 `uv = a·v + b`：

| 组件 | 拟合 (rms) |
|---|---|
| 上半身 | `uv_x = vx/1100 + 0.5`, `uv_y = -vy/1106 + 0.5` (rms 1.5e-8 / 2.2e-8) |
| 嘴巴 | `uv_x = vx/134 + 0.5`, `uv_y = -vy/113 + 0.5` (rms 1.5e-8 / 2.0e-8) |
| 眉毛 | `uv_x = vx/465 + 0.5`, `uv_y = -vy/136 + 0.5` (rms 1.4e-8 / 1.9e-8) |

即 **`uv = (v / size) · (1, −1) + 0.5`**，精度到浮点噪声。含义：
- 平面 puppet 的顶点坐标**就在纹理像素空间**，且**以纹理中心为原点** (故 `+0.5`)；
- Y 轴反向 (纹理 v 向下 / 网格 y 向上)；
- `size` 同时是顶点空间的度量 —— 网格 bbox/UV 跨度 = size 也在这些组件上精确成立。

对这类网格，我方 "按 bbox 绘制 + 按 UV 采样" 与官方**同构**，几何上不可能产生拉伸。

## 三、顶点/UV 字节布局已确认 (stride=80, UV@+72)

用恒等式当判据，在原始顶点字节上穷举 `stride ∈ {64..112}` × `uvOff ∈ {4..stride-8}`：

- Mutsumi 全部组件：**score 最小解唯一为 stride=80 / uvOff=+72**，rms≈1e-5，最佳解比第 20 名小 5 个数量级 (判据锐利)。
- ⇒ `lib/we-renderer/puppet.js:490-499` 的布局假设 (pos@0, blendIdx@40, weights@56, uv@72) **正确**。

## 四、非平面网格：恒等式不成立 (待解释)

皓风琦 N / nv、十字架、Plana 人物：**所有** stride/uvOff 组合都无近零解
(N 最佳 rms≈9.4e2 纹素，判据模糊)。含义：这些网格的 UV 不是位置的平面仿射函数 ——
即网格**不是**平铺在纹理平面上的贴片 (含深度/曲面/预变形)，或存在第二套 UV/包裹语义。

这解释不了 "单方向拉伸" 本身，但排除了 "UV 解析错误" 这一假设。
剩下的候选：`autosize`/`clampuvs`/`cropoffset` 的官方消费点，以及网格空间→canvas 的映射系数
(需要官方代码，见 `docs/WE-OFFICIAL-TRANSFORM-NOTES.md`)。

## 五、顶点空间 = 纹理像素空间 (雅可比证明, 普适)

前四节的仿射拟合会被"图集分块"(piecewise affine) 污染 —— 一个网格把多块纹理拼在一张图上时
整体拟合 rms 很大, 但**局部**映射仍然精确。改用逐三角形雅可比 `J = ∂(u,v)/∂(x,y)`
(对三角形 (v0,v1,v2)→(uv0,uv1,uv2) 解 2×2 矩阵), 取奇异值/对角元:

- `σ1/σ2` (局部各向异性) **精确等于声明 size 的宽高比**;
- `T_x = 1/|∂u/∂x|`, `T_y = 1/|∂v/∂y|` (隐含纹理尺寸) **逐轴精确等于 size**;
- 非对角/对角中位数 ≈ 0 ⇒ 轴对齐 (无旋转); `十字架` 例外 (0.287 ⇒ 该网格本身带旋转,
  其 T/size = 1.040 仍一致)。

实测 (`scripts/tmp-mesh-scale.mjs`, 5 个壁纸 13 个 puppet):

| 组件 | size | T_x / T_y | T/size |
|---|---|---|---|
| 皓风琦 N | 3334x2501 | 3333.4 / 2501.2 | 1.000 / 1.000 |
| 皓风琦 nv | 2568x2027 | 2568.0 / 2027.0 | 1.000 / 1.000 |
| 皓风琦 十字架 | 165x366 | 171.6 / 380.7 | 1.040 / 1.040 (含旋转) |
| Mutsumi 上半身 | 1100x1106 | 1100.0 / 1106.0 | 1.000 / 1.000 |
| Mutsumi 嘴巴 | 134x113 | 134.0 / 113.0 | 1.000 / 1.000 |
| Mutsumi 眉毛 | 465x136 | 465.0 / 136.0 | 1.000 / 1.000 |
| Plana 人物 | 3550x3750 | 3550.0 / 3750.0 | 1.000 / 1.000 |
| 手部组合 / 08眼组 / 02眉毛 | 1317x1000 / 433x432 / 265x148 | 逐轴相等 | 1.000 |

**结论 (对实现有约束力)**:
1. puppet 顶点空间**就是**纹理像素空间, `uv = v / size (+ 每块偏移)`。因此四边形尺寸
   = 网格 bbox × 对象 scale × 投影尺度, 即我方现行实现 —— **尺度正确, 无需任何归一化**。
2. "按 size 铺满"(`93cf865`/`60bac1e`) 在语义上必然错误 ⇒ `a438e50` 的回退是正确的,
   这条线**彻底关闭**, 不是"待定标"。
3. 皓风琦的"单方向错误拉伸"**不可能**来自 puppet 几何/四边形尺寸 —— 嫌疑转向
   **蒙皮姿态 (MDLA 动画层混合/骨骼 scale)** 与**效果链** (N 带 shake、nv 带 workshop 效果)。

## 六、其他实测

- `clampuvs` 是 3640755971 场景对象的键之一；十字架 UV 跨度 = [-0.018, 1.018] × [-0.008, 1.008]
  (超出 [0,1])，N 的 UV = [0.003, 0.972] × [0.007, 1.000]。包裹/clamp 语义未定。
- Plana 人物对象带 `parallaxDepth` 键 (其余测试对象无)。
- 皓风琦所有对象均无 `material` 键 —— 材质路径只在模型 JSON (`{autosize, material, puppet}`) 里；
  材质 JSON 的 `passes[0].textures[0]` 是**裸名** (如 `"N"`)，实际文件为 `materials/N.tex`。
