# ADR-0008: 玻璃配置的「两态」模型与门控策略（glass config: two-state model & gating policy）

- **Date**: 2026-10-03
- **Status**: Accepted
- **Revised**: 2026-10-05 —— D4 细化并**恢复生效**（见 D4 的"修订"一段：2026-10-03 晚些时候
  有一版实现按当时口径把这道门整体拆掉、做成"两档同内容"，但**本 ADR 没有随之修订**，
  于是文档与实现自那天起不一致；2026-10-05 按 D4 恢复并把分类写死。）
- **Deciders**: 用户（产品口径）+ 实现（本仓）

## Context

玻璃子系统的取值管道原先由**四件事共同决定**：两条解析路径、三个键三种状态
（"要不要玻璃" / "是否独立" / "这一项有没有能力读自己的值"）、各面不同的量纲、
以及"门控靠 body 属性与字符串约定"。后果是"用谁的值"这一件事被两个键同时回答，
而两者各自还有一张默认值表；量纲不同又逼着"继承"必须做归一化换算。

可测事实（用符号名与路径作锚点，不写行号与数值）：

- 取值入口是 `glassValue(surface, param, own, global)`（`src/glass.js`）；
- 设置真源是 `lib/settings-schema.js` 的 `KINDS` / `DEFAULTS` / `readOne` / `migrateSettings`；
- 判据在 `test/verify-glass-surfaces.mjs`；"有效取值"的等价性由一份**未入库**的等价性探针
  在多个状态下逐项比较（口径与复算方式见归档的 wip §10.9 —— 入库文档不指向本机专用路径）。
- 两次实测反例：① 全局「雾化」在"跟随"档被旧解析器按**另一套量纲**放大（把一套刻度当另一套用）；
  ②「玻璃透明度」拖过旧上限时**跳回默认值** —— 因为 `clampNum` 的语义是
  "在范围内就用、否则回落到默认值"，**不是截断**；而处理器的取值域是手写的、会与 `KINDS` 漂移。

## Decision

**D1 — 每个面两态。** "读全局"与"读自己"由**一个**键回答（`glassMode`: `'inherit' | 'custom'`）。
"这一项有没有能力读自己的值"不再手抄成一张能力表；它由"注册表 `params` ↔ `glassValue` 调用点"
的**逐参数对账**与"写出的变量必须有人读"两条判据共同保证。

**D2 — 一把刻度。** 各面共用同一套**存储**刻度（模糊类一把、透明度类一把），各面的曲线只负责
"位置 → 观感"的表达。"继承"于是等于"读另一个键的那个数字"，归一化换算（`norm` / `denorm`）被删除，
调用点只传裸值。刻度真源在 `KINDS`，曲线分母由判据与它对齐。

**D3 — 门控分两类。** ①**恒挂**：原先"每个子面要不要玻璃"的门控已退役（见 Consequences），
相关属性恒为"开"；②**可切**：既有面的显示开关仍成对挂/摘自己的属性。
门控属性继续作为 CSS 侧"哪些规则画玻璃"的**证书** —— 门控覆盖率与许可证检查都靠它。

**D4 — 简化配置 vs 复杂配置。** 全局四件套 = **简化配置**（两档 surface 都画）；
**「独立配置」层 = 复杂配置**（只在设置菜单出现）。判定走 `ctx.surface`。

> **修订 2026-10-05（用户口径，分类写死）**：两档的分界以**"是总开关还是独立配置"**为准 ——
> · **简化配置**（侧栏档 + 设置页都画）：全局四件套（玻璃颜色 / 玻璃透明度 / 雾化 / 玻璃保真度），
>   以及每个面的**总开关** ——「思考块液态玻璃」「左侧栏液态玻璃」「侧栏液态玻璃」
>   「侧栏全透明」「侧栏玻璃跟随全局」；
> · **高级配置**（只在设置页画）：每个面的**「独立配置」层及其子项参数**，以及挂在总开关下面的
>   **细调行**（「思考块液态玻璃」门下的胶囊雾化 / 胶囊颜色，左侧栏与侧栏 / 内容面的独立参数）。
> · **预设方案 = 高级配置**（只在设置页画）：显式门 `!sidebarSurface && renderGlassPresetsBlock(...)`
>   在 `src/glass-panel.js`；`glassPresets` 进 `quick-panel` 的 setting-only 占位器（拆掉门 ⇒ 渲染器
>   解构它的第一下就炸）；`verify-scene-live` 两档都钉（侧栏档的**标签序列与整树文本**都不许出现
>   预设块，设置档必须有 —— 用例补了 `ctxOver` 注入 preset 替身，否则那条断言会恒假）。
>   分类理由：它既不是"总开关"也不是"逐面覆盖"，而是**跨面批量覆盖**（一份预设 = 玻璃子系统完整
>   快照，应用即 `Object.assign` 整套覆盖、**无确认也无撤销**），且出厂预设**删除即永久**
>   （墓碑、无恢复通道）⇒ 按 D4 的取向属高阶；侧栏是窄面板 + 随手调的场合。
>   ⚠️ 这条此前是**隐式**的：侧栏档只是"没传 `glassPresets`"，靠渲染器入口守卫
>   `if (!presets) return null` 顺带不画，当时没有任何判据对着预设块判过 ⇒ 谁把字段补进侧栏 ctx，
>   它就会静默出现。2026-10-05 已显式化（门 + 占位器 + 两档断言）。`docs/CHANGELOG.md` 里
>   "设置页与侧栏快捷面板共用同一预设块"那句与实现不符（上游文案过宽），同批更正。
>
> 与门配套的第二道保险是 `src/quick-panel.js` 的 **setting-only 占位器**：侧栏档不再画的那些
> 处理器在那份 ctx 里是"取用即抛错"的替身 ⇒ 将来把高级行挪回侧栏档会**当场炸**，而不是静默
> 变成"拖了没反应"的死旋钮。判据：`verify-scene-live` 的「侧栏 ctx 覆盖渲染器要的全部字段」与
> 两档**控件标签序列**（`CASES`/`MORE_CASES` 两侧都钉，含"侧栏档一个「独立配置」都不许有、
> 但两个总开关必须在"的双向断言）。
>
> 背景：2026-10-03 曾有一版实现按当时口径把这道门拆掉（"侧栏「外观」与设置页完全同内容"），
> 但**没有修订本 ADR** ⇒ 文档（本条 + `docs/UPGRADING.md`）与实现不一致了一整天；本次以 ADR 为准恢复。

**D5 — 每个被读的面都必须有开关。** mode 的**可达性**是判据：凡 `glassValue("面", …)` 读到的面，
必须要么在登记表里（面板按表自动渲染开关），要么有至少一处显式的开关调用点。
理由：没有入口的 mode 永远停在默认值 ⇒ 那个面的专属滑块全是**死的**（实测发生过）。

**D6 — 迁移按参数性质分档。** **位置量**（有曲线，如透明度）按**占比**换算，保证归一化位置不变；
**直接量**（本身就是 px，如模糊）**只钳制、不换算** —— 对它做换算等于改观感。
版本标记与分档逻辑住在 `migrateSettings`；旧档的"旧默认值残留"与"用户显式选择"要区别对待。

## Consequences

- **收益**：取值只有一条路径、一个真源；"全局一套语义"成立；每一层都有判据（含负对照），
  于是"旋钮无入口""写了没人读""判据恒真"这几类退化都能被判据当场挡住。
- **放弃：按面变量间接层。** 曾经想让每个面在**共享 CSS 规则**里读自己一套变量。该方案被**证伪**：
  可读性契约把若干声明钉在**固定文本形状**上（面纱形以特定变量名开头、回退配方要求逐字共享），
  在共享规则里插一层变量名就会破坏它们。⇒ 代价是"逐面独立"只能走
  **改全局变量的取值来源**这条路（侧栏与内容面即此），不能靠改共享规则。
- **放弃：关闭某一面即"回原生纯色"。** 实测摘掉门控属性并不能如愿回到原生 ——
  那些面上还有一批**不挂门控**的令牌改写（壁纸激活即生效），"关"得到的是半玻璃。
  要做到"关得像样"必须连令牌层一起回退，复杂度远超收益 ⇒ 整层退役，改为**恒吃玻璃**。
- **迁移代价**：旧存档的刻度值会被一次性重写（观感逐点不变，但存储数字变了）；
  超出新刻度的直接量（模糊）会被钳到新上限 —— 这是刻度的真实上限，已明记为代价。

## 重新考虑的触发线

- 若要让"逐面在共享规则里读自己一套变量"重新可行：先确认可读性契约**不再**把声明钉在固定文本形状上。
- 若某个面的「独立配置」要放进简化配置：重开 D4（简化/复杂边界是产品口径，不是实现选择）。
- 若要把"恒挂"的门控属性改回可关：需要先让**令牌层**也能整组回退。
- 若新增一个玻璃面：D5 的判据会要求你同时给它一个开关；漏了会红。
