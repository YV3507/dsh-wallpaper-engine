# ADR-0009: 本机字体清单由宿主问操作系统（中英）

- **Date**: 2026-10-02
- **Status**: Accepted
- **Deciders**: 插件维护者

> English: 术语与中文逐条对应；本文的**决定**是三条 D1–D3，README 与 `docs/FONT-SYSTEM.md` 只回声结论。

## Context

用户要能选**本机已安装的字体族**（不只是随包那几个内置族键），并要求"全局"与"终端"两个作用范围。
于是必须先回答一个问题：**这份族名清单从哪来**。三条候选路，各自的代价都在本仓可核对：

- **浏览器侧自测字形宽度**（`document.fonts.check` / 逐名量宽）。唯一不依赖宿主的一条路，
  但它**必须先有一份候选名单**才能"测" —— 而候选名单正是要解决的问题（鸡生蛋）。
  它只能验证"某个名字在不在"，不能枚举。
- **插件自己解析字体文件**（读 `.ttf/.otf/.ttc` 的 `name` 表）。三平台都能用、不依赖外部程序、
  一次扫描很快。代价是本仓要多一份**二进制解析器**（ttcf 集合、UTF-16BE 名字表、`.dfont` 资源叉），
  而它的失败形态是"给出一个**看起来很像**的错名字" —— 比"给不出名字"坏得多。
- **问操作系统**（macOS `system_profiler` / Windows PowerShell 的 `InstalledFontCollection` /
  Linux `fc-list`）。族名口径就是系统自己的口径，实现是几条解析函数。代价写在下面 D3 与
  Consequences 里。

## Decision

**D1 —— 清单由宿主枚举并缓存，浏览器侧只是读者。**
浏览器拿不到"系统装了哪些字体"（防指纹），宿主拿得到；两半之间只经同源 HTTP 路由（本仓既有边界）。
客户端通道（`src/system-fonts.js`）只做"要一次 / 缓存住 / 说清失败"，与字体集通道同形。

**D1′ —— 名字要**两种写法都给**（macOS 上因此有第二条权威腿）。**
`system_profiler` 报的是**本地化**族名（中文系统上 `PingFang SC` 报成 `苹方-简`），而 CSS /
字体册英文界面 / 设计软件用的是**规范（英文）名**；本插件的内置族键（`STXingkai` / `KaiTi` …）
也是英文名。只给本地化名时，用户在"本机字体"里找不到自己认识的字体 —— 现场反馈就是
"可选字体没有扫描出本机所有字体"（字体在，名字对不上）。所以 macOS 上并行跑**两条权威腿**
（`system_profiler` 出本地化名 + CoreText 出规范名），族名**取并集**：两种写法都能选到。
两条腿并行 ⇒ 慢的那条决定耗时，冷扫描不会因为多一条而变慢。

**D2 —— 族名一律当"值"传，不当"栈"传：存族键 `sys:<族名>`,CSS 栈在解析侧现拼。**
本机字体没有静态白名单 ⇒ 值域只能是"名字能不能安全进 CSS"（共享内核判：禁引号/反斜杠/分号花括号
与控制符，限长）。栈由客户端拼成 `"<族名>", var(--we-host-font-family, <保底链>)`：
**先用自己的族名，再退回 DSH 原来那条字族链的运行时快照** —— 抄一条 fallback 链到自己代码里，
只会在下一次 DSH 调整字族时漏改。

**D3 —— 权威来源做不到时**按字体文件名推**，并如实标 `approximate`。**
三条权威来源都可能不在（工具缺失、服务被裁、超时）。这时给一份"按文件名推测"的清单比给空清单有用，
但**必须带标记**：面板上写明"是按文件名推测的"。宁可说清是推测，也不让一个猜出来的名字看着像真的
（与"内嵌 MP4 探测未命中一律 `未知 → null`"同一口径）。

**D4 —— 扫描只在第一次真的用到时发生，且双层缓存 + 过期先回旧值。**
不在 `apply()` 里做（启动期零写盘的纪律，也是"没隔离数据目录的守卫不会被污染"的前提）。
过期时**先回旧值**（标 `stale`）再后台重扫 —— 面板不该因为一次系统调用而卡住。

## Consequences

- **收益**：族名口径 = 系统口径，而且 macOS 上**两种名字都在**（实测 `"苹方-简"` 与 `"PingFang SC"`
  在 Chromium 里渲染宽度逐位相同 ⇒ 选哪个都命中同一个字体）；跨平台差异被收进几条纯解析函数里，
  可以用夹具机械判（守卫只在"多字节解码"那一条上真起子进程）。
- **代价 1（最重要）**：**macOS 那条慢腿很慢**（`system_profiler SPFontsDataType` 会遍历全部字体，
  实测秒级到十秒级；`-detailLevel mini` 不减少耗时）。所以本决定**依赖缓存**：
  没有缓存时第一次请求会等一次完整扫描（有超时上限，超时即降级）。这是本功能唯一的"第一次慢"——
  CoreText 那条腿只要几十毫秒，所以**两条腿并行**不会让它更慢。
- **代价 2**：插件多了一个**子进程调用面**（平台工具名与参数进代码，macOS 上是两条）。
  已按"有超时、有输出上限、超时即 kill、按字节解码"封口，且不进启动路径。
- **代价 3**：清单里**同一个字体可能出现两个名字**（`PingFang SC` 与 `苹方-简` 各占一行）。
  这是刻意的：原生 `<select>` 的首字母跳转按**选项文本**匹配，两条独立条目才能"打 Pin 跳到
  PingFang"或"打苹跳到苹方"；合成一行标签（`苹方-简 (PingFang SC)`）反而两边都跳不到。
- **放弃了什么**：① "插件自带字体文件解析器"（D1 的第二个候选）—— 少一份二进制解析代码与它的
  错名字风险，换来"依赖系统工具 + 必须缓存"；② "让用户手填字体名"（本机字体枚举的就是它）；
  ③ **在宿主侧预筛掉系统保留字体** —— 那条路走不通：能不能按族名取到是**浏览器**的事实，
  宿主那边只有"系统列了哪些名字"。
- **已修的三个现场缺陷（都属于本决定落地时的形态问题）**：
  ① **系统列出的族名 ≠ 浏览器能匹配的族名**（现场反馈："控制台切换了字体，部分特殊文字还是显示成口"）。
  macOS 把相当一批字体**只给系统用**（`Apple Color Emoji` / `Symbol` / `Zapf Dingbats` / `Apple Braille`、
  阿拉伯/希伯来/天城文那些），`system_profiler` 照样列，但浏览器按族名取不到；同一字体的**另一种写法**
  （`苹方-繁` 有、`PingFang TC` 才取得到）也一样。实测本机 309 个名字里 **64 个**属于这类 ⇒ 用户选它
  **什么都不会发生**，看着就是"功能坏了"。⇒ 客户端在渲染下拉时探一次"这个名字在本浏览器里能不能用"
  （同名分别配 monospace / serif 量同一段拉丁文字，宽度相同才算能匹配），用不了的略掉并如实报数。
  这条**只能在客户端**做：能不能匹配是**浏览器**的事，宿主（Node）侧根本没有这个事实。
  ② 只有本地化名 ⇒ 用户找不到自己认识的字体（D1′）；
  ③ 子进程输出**逐块 `toString('utf8')`** 拼会在多字节字符跨块时插进 U+FFFD，
  实测把 `系统字体` 变成 `系统\uFFFD\uFFFD\uFFFD体`，于是同一个族在清单里同时有"好的"和"坏的"
  两条。现在按**字节**收、最后一次性解码。

## 落地时新长出的一条：终端字体投两个终端

「终端字体」这一个键要管**两个**终端，而它们的投递机制完全不同：

- **DSH 对话里的终端块**：官方 `--dsl-terminal-font` 钩子（CSS 自定义属性，值可以是 `var()` 链）。
- **侧栏 / SSH 的终端面板**（`@linxin666/dsh-ssh` 的 **xterm**）：xterm 的字体只从构造参数/选项来，
  **普通 CSS 规则改不动它**（它自己源码里写着这句话）。它给这种情况留了**给皮肤用的**变量
  `--dsh-ssh-terminal-font`（读 `getComputedStyle(document.body)`），我们写那一个。
  ⚠️ 这一份必须是**摊平的具体字体列表**（不能含 `var()`）—— 它会被当字符串交给 `fontFamily`。
  ⚠️ 而且**时机是承重的**：那个插件只在**构造终端的那一刻**读它（之后只有它自己的设置变化才重读），
  所以这一份必须写成 **body 上的内联属性**、并在 bundle 正文**顶层先抢跑一次**（用同步可读的本地缓存）——
  写成样式表规则会输给"宿主异步回话"那段延迟，终端在那之前就建好了（实测症状："重启了还是口"）。

**代价**：多了一条**依赖第三方插件内部接缝**的投递路径。它没有守卫能兜（判据只能断言"我们写了这条规则"，
断言不了"那个插件还在读它"）：`dsh-ssh` 改钩子名 / 改读取位置，这条会**静默失效**（症状回到"口"）。
换来的是"一处设置真的管住了用户看得到的那个终端"，比让用户去另一个插件的设置里自己找要值。

**让位规则**：`dsh-ssh` 自己的设置 `terminalFontFamily` 优先级高于这个钩子 —— 那是它的取值链，
我们不改写别人的设置，也不抢它的优先级。
## 重新考虑的触发线

- **系统工具被裁**或某平台上长期拿不到族名（降级路径成为常态）⇒ 重新评估自解析路线。
- **macOS 那条扫描变得不可接受**（例如冷启动路径上被调用、或耗时继续增长）⇒ 考虑后台预热
  （`apply()` 之后空闲时扫一次），或干脆只用 CoreText 那条快腿（代价是丢掉本地化名 —— 那正是
  D1′ 要保住的东西，所以要走这一步得先有"本地化名从别处来"的答案）。
- 上游 DSH 自己提供了"系统字体清单"服务 ⇒ 直接改用它的口径，本路由降级为兼容层。
