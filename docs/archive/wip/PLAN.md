#### 为什么**不**做"改了瞬态字段必须有 `emit()`"那条腿

计划原来把这条列为根因③。取证后发现**它不能机械化**，硬加会与既有设计冲突：

- `src/video-layer.js` 里 `selection.transcodeProgress` 的写入**明确标注** `NOTE: no emit() here —
  this runs inside syncLayers (already inside an emit …)` ⇒ 缺 emit 是**上下文决定的正确行为**，
  要机械化就得做"这个函数是否在 emit 之内"的**传递调用图分析**，那是另一个量级的工程；
- 转码进度**本身是轮询驱动**的（`/transcode-progress`，面板注释写明 polled），所以"没 emit 就不更新"
  这个前提在这个子系统里**不成立**。

⇒ **结论**：那条腿改成**登记 + 人写理由**（表里每一行的 `why`），而不是机器判定。
判断归人，机器只保证"这个字段有人认领过、且认领理由写在明处"。

> **已做（2026-10-04，未提交）**：10 个模块全部补上 `export { … }`（单块多行；三个"顶层声明带缩进"的

> （`await import(new URL('../src/picker-model.js', …).href)`），并立了三件事：
> ① 导出清单 == 本文件钉住的 API 面（**守着导出的名字，而不是手抄一份 API 清单**）；
> ② **双通道对拍**：24 条用例逐条判「产物里那段内联副本」与「直接 import 的源模块」投影相同
>   ⇒ 同时证明**构建保真**与**导出接口是活的**；
> ③ **自足的有牙证明**：把同一份源码文本里的 `const PICKER_PAGE_SIZE = 24` 变异成 `25`，
>   断言同一条判据**当场判出**，而未变异的那份在**同一条判据**下通过（正负成对）。
>   ⇒ 不依赖"临时改坏源文件"那种不可留仓库的手法，证明是可重复的。
>
> **这个形状就是 §4 期 2 的样板**：`import` 源模块做行为断言 + 与产物对拍 + 自足变异探针。
>
> ⚠️ **做这一步时暴露的两件事，都值得记住**（都是"没有导出块"一直在掩盖的东西）：
> 1. **守卫会直接求值原始 `src/` 源码**（`new Function` / `vm.Script`），而那里 `export` 是语法错误。
>    实测三处：`verify-scene-live`（quick-panel 复现台 ×2）、`verify-i18n`（i18n 运行时沙箱）、
>    `verify-client`（effects 段，**早就自己剥了一份正则**）。已收成**共享实现**
>    `stripExportBlocks`（在 `test/tools/js-text.mjs`，带自检 4 条正负对照）——
>    以后新增这类求值台必须复用它，别再各抄一份正则。
> 2. `scripts/build-client.mjs` 的**机器提取撞名**原本用 `^` 行首锚点，漏掉那三个带缩进的模块
>    ⇒ 撞名不被判出（平铺后是运行期 SyntaxError）。已改成"缩进 == 本文件声明最小缩进"。

`src/` 28 个模块里 **10 个**没有导出块（`client.js` 是正文，豁免）：
`i18n`(25 个顶层声明) `i18n-copy`(2) `layer-core`(11) `nav-icon`(5) `picker-model`(16)
`picker-modal`(1) `picker-props-panel`(1) `sidebar-right`(27) `about-assets`(3) `quick-panel`。

[`CODE-STRUCTURE.md`](../CODE-STRUCTURE.md) §5 第 5 条写明了这条：
「`src/` 模块用 `export { … }` 列出对外名字…**导出清单同时是守卫的接口**（守卫直接 `import` 模块做行为断言）」。
后果**可观测**：因为 `picker-model.js` 没有导出，`test/verify-picker-model.mjs` 只能写
`inlinedSection()` 从产物里切字符串再 `vm` 求值——全仓唯一这么做的守卫。

**修法**：各文件顶部补 `export { … }`（内容 = 已有顶层声明中对外真正被用的那些），**不改逻辑**。
`build-client.mjs` 会剥掉它，对产物无影响；唯一风险是「导出名与 `client.js` 正文冲突」，
由构建期的**机器提取**兜住（冲突即构建失败）。

**完成判据**：`node test/verify-client-sync.mjs` 绿；每个模块都有导出块；
**并且**至少把一个守卫改成**直接 `import` 该模块**做行为断言（样板：`test/verify-theme-layer.mjs`
的 `await import(new URL('../src/font/color-roles.js', …))` + `installWeTShim()`），
且证明它在「模块被改坏」时**会红**。

## 2. `src/` 注释审计（简洁 · 稳定 · 高时效）

**它不是新纪律**：这三条就是 [`docs/README.md`](../README.md) §写作纪律 1 / 2 / 4 —— 只是**从没有人核对过**。
`src/` 注释不是"给人看的草稿"：构建**不剥注释**，它随 `lib/client.js` **发给每个用户**
（实测：内联模块段 **1,453 KB** 里注释行占 **270 KB / 18.6%**；`src/**` 注释占源码 **29%**）。
⇒ 口径冲突时**文件头 > 本节**。

### 2.1 三类判据（**先分类再动手，否则会删掉该留的**）

| 类 | 处置 | 判据 |
|---|---|---|
| **留** | 不动 | 不变量 / 契约 / **带出处的实测值**（§写作纪律 2 的明文**例外**）。基线：**205** 行命中"不变量/契约"关键词；`实测` 类 **94** 行 |
| **删** | 整行去 | 历史框定（此前 / 曾经 / 原先 / 旧行为 / 已随…退役）**45** 行 · issue/PR 号 **43** 行 · 修复史 **4** 行 · 日期 **1** 行 |
| **改写** | 换形式 | 会漂的数值 **209** 行 · 把"为什么"写成散文的（该进 [`adr/`](../adr/)） |
| **改口** | **必须改，不能删** | **注释与实现互相矛盾**（注释描述的是已废弃的设计）—— 这类最危险：读者照着注释去理解代码会得出**相反**的结论 |

> **`改口` 类的第一个实例（批次 2，2026-10-04）**：`src/quick-panel.js` 头注释 + 行内注释写
> 「壁纸属性**在列表下方内联展开**（不做整区替换）」，而实现是**页内下钻**（内容区整区换成面板、
> 列表与搜索栏让位，`we-qp__propsview--drill`）。文件头别处与 `styles.js`、行为判据
> （`verify-scene-live` 「下钻后：列表 / 搜索栏让位，内容区**直接就是面板**」）**都是下钻口径**
> ⇒ 只有那两处注释是旧设计的残留。已按实现改口。
> **它怎么被发现的**：死声明判据（`verify-dead-declarations`）报出 `test/verify-scene-live.mjs`
> 里的 `tabBodyOf` —— 我为它补判据时才发现"它要判的顺序在实现里根本不存在"，于是从
> 「补一条判据」变成「删掉死代码 + 改口两处注释」。
> ⚠️ **教训**：死代码不只是"没用的代码"，它经常是**旧设计的化石**；
> 顺着它的意图补判据之前，先确认那个意图**今天还成立**。

**两条不能误伤的红线**：

0. **先剥注释再数**（实测教训）：我第一版审计脚本在**未剥注释**的原文上数，
   把 `quick-panel.js` 契约注释里那句 `` `selection.X =` `` 算成一处置写 ⇒ 报了一个**不存在的候选**。
   判据本身一直是正确的（`stripComments` 之后注释不进判据）。
   复算必须照 `test/tools/js-text.mjs` 的口径先剥注释 —— 否则这一节会从"审计注释"变成"用注释骗自己"。
1. **「实测 X ≈ Y」要留**（README 原话：「否则读者分不清『测出来的』与『猜的』」），
   只做 `把出处钉在数值旁边`。`src/video-layer.js` 那句 `764,688,296B/1761ms` 是**合法**的——
   它解释了 faststart 变体的存在理由。**删它就等于把根因删了。**
2. **会漂的数值要"搬进符号"，不是删掉**：注释里写死的常量值 → 改成引用代码里的**具名常量**，
   注释只讲它为什么是那个量级（`≈430MB/s` 这类实测结论可留）。判据：`grep` 注释里的数值与
   `lib/settings-schema.js` / `CONSTS` 的真源**是否两处**——两处就是腐化源。

**issue/PR 号（43 行）单列**：README §写作纪律 1 明写"历史价值的内容进 `CHANGELOG.md` 或 git 历史"。
但**先核对再删**——外部编号是"稳定性最差"的信息（issues 会关、会重组），
而其中可能藏着**真正的不变量**。做法：逐条读，是**理由**的 → 改写成自足的表述（或进 ADR）；
纯**溯源**的 → 删，依据交 git 历史。

### 2.3 候选是怎么数出来的 · 以及为什么**不**加机器判据

**复算命令**（本节所有计数都出自它）：审计脚本把注释文本逐行分类（历史 / 漂值 / 不变量），
逻辑同 `test/tools/audit-guard-teeth.mjs` 的立场 —— **只给候选，结论要人读**。
脚本**还没入库**：若本节走完仍值得长期保留，就在 `test/tools/` 下建一个审计脚本
（拟名 `audit-comment-decay.mjs` —— **现在不能写链接，它还不存在**）
并在 [`DEV-GUIDE.md`](../DEV-GUIDE.md) §4.6 **点名**（那是明文要求：`test/tools/*.mjs` 必须被点名，
否则等于只对作者可见）；**一次性用完即随本节删掉**。

```sh
# 分类口径（与本节表格同源）：
#   历史候选 = 此前|曾经|原先|旧行为|已随…退役|20\d\d-\d\d-\d\d|#\d+|实测/真机/踩过/一度
#   漂值候选 = ≈\d|\d+ms|\d+s|\d+%|\b\d{3,}\b|"N 行/N 处/N 个文件"
#   ⚠️ 「裸大数」有假阳性（十六进制色值、px、`764,688,296B` 这类**带出处的实测值**）⇒ 必须人读
```

**为什么不加机器判据**：[`adr/0006`](../adr/0006-comment-discipline-as-written-convention.md)
已把文档/注释类守卫**整体下线**，理由是「作者会去躲词表，且守卫自身会腐化」；
[`adr/0007`](../adr/0007-machine-checks-target-code-not-prose.md) 把它定成边界：
**读代码的守卫照留，读散文的守卫不加**。上面那三个正则**是工作清单，不是判据**。

> 唯一**可能**站得住的机器判定是「注释里的数值与真源不一致」——
> 但那要求数值有一个**可机读的真源**（`lib/settings-schema.js` / `CONSTS` 那类）。
> 若要加，只加这一条，且必须按 §4.7 约定 5 写正负对照；**其余三类一律不加**。

### 2.4 结论落点

- 机制 / 不变量 → **就留在文件头**（本节的目的正是让它们成为文件头里**唯一**的东西）；
- 被删掉的**为什么** → [`adr/`](../adr/) 或 `CHANGELOG.md`（§写作纪律 1 指的路）；
- 审计脚本 → 见 2.3（长期有用则进 `test/tools/` 并被点名；一次性则删）。

## 3. `src/` 目录结构

**准入规则只有一条**（[`CODE-STRUCTURE.md`](../CODE-STRUCTURE.md) §4 第 1 条）：**两条门槛同时满足**——
① 成员数达守卫里的常量 `SRC_DIR_MIN_MEMBERS`（真源在 `test/verify-module-layout.mjs`，别抄）；
② 有自己的一份权威文档且其**一级标题**点名该目录（**纯约定，无守卫**）。
判前必知：`src/` 模块之间**没有 `import`**、目录在这一侧**不承载机器含义**，
唯一用处是「让人一眼看出这几块是一伙的」；fan-in/fan-out 高多是**门面装配耦合**，不是家族信号。

现状：根 **24** + `src/font/` **4**。`src/font/` 是唯一两条都过的（4 个成员 + `FONT-SYSTEM.md` 一级标题点名）。

| 候选 | 成员 | 门槛② | 家族内耦合 | 结论 |
|---|:--:|:--:|---|---|
| `src/font/` | 4 | ✅ | 13 / 10 次 | 不动（是模板） |
| **picker 家族** | 4 | ❌ 需新建文档 | `modal → model` 30 次 | **可选做**：新建一份权威文档（拟名 `PICKER-SYSTEM.md`）把现在分散在三个文件头里的规则收成一处（类名是契约 / 两套模式 / `(ctx)` 四类越界） |
| 渲染器层 | 4 | ❌ 无也不该有 | **互相零读取**（只读 `client.js`） | **不做**：它是同一**架构层**，不是一个**协作家族**；且与 picker 归属冲突，规则未定优先级 |
| 媒体管线 | 5 | ❌ | `live-layer` 被家族内读 | **不做**：`video-layer` 独立的**全部理由**就是「**不**在 live 那条路里」（真机踩过十几秒纯色帧），收进一层正好抹掉这条边界 |
| 设置通道 | 6 | ❌ | 互读少 | **不做**：`fontset-store` 头注释明写「**另立一条**而不是并进 persistence.js」（真源/键集/失败语义都不同） |
| 无 ctx 基座 | 8 | ❌ | **零互相读取** | **不做**：它是 §3.1 的一张**角色清单**，不是一伙人 |

**明确不做的四件**：按文件名前缀机械分组（`video-layer` 与 `live-layer` 前缀同、却是两条刻意分开的通道）·
按 fan-in 聚类 · 把「不读 `selection`」当分组依据 · 同时开两个新目录（`picker-modal` 归属冲突）。

**成本**：搬 4 个文件 ≈ 1–2 人日（含 `npm run build`、`verify` 全链、新文档）。
搬动连带面约 **545 处**（`test/` 241 · `src/` 互引 148 · `docs/`+README+package.json 122 · `scripts/` 34），
其中只有 25 处会当场断链，其余不报错。

**结论落点**：裁决（做/不做 + 一行理由）进 [`CODE-STRUCTURE.md`](../CODE-STRUCTURE.md) §3.1 的分工表 / §4 的反例清单。
**不新建文档**；若做 picker 目录，才建那一份权威文档（门槛②要求它存在）。

## 5. 顺序与闸门

**拓扑序**：`1.1 修扫描面` → `1.2 补导出`（可与 1.1 并行） → `§3 结构裁决并冻结` → `§4 测试重构`；
**§2 注释审计**与三者的关系见下面「禁止交叉」。

反了会怎样：不先修扫描面，§3 一建子目录，被搬进去的文件**立刻从棘轮消失**（缺陷在重构中被放大）；
不先补导出，§4 期 2 对那 10 个文件不可用；§3 未冻结就动 §4，刚建的映射要重做一遍。

**每步闸门**：

| # | 闸门 | 命令 |
|---|---|---|
| G1 | 产物与源码同步 | `node test/verify-client-sync.mjs` |
| G2 | 硬档全绿 | `npm run verify` |
| G3 | 软档**没变差**（不是"绿"） | `npm run verify:docs` |
| G4 | 冒烟全绿 | `npm run smoke` |
| G5 | 搬迁/新增的判据**有牙** | 中和判据 ⇒ 负对照必须变红（§4.7 约定 8） |
| G6 | 扫描面**非空转** | 「零违规」型判据必须同时断言扫描面地板 |
| G7 | 文档与纪律**同一次提交** | `CODE-STRUCTURE.md` §6 上方明文 |
| G8 | 路由索引重算 | `node test/tools/host-route-index.mjs --write`（增删守卫会改其「守卫提及」列） |
| G9 | **改注释 = 改产物**（§2 专用） | 构建**不剥注释** ⇒ `src/**` 的注释改一行，`lib/client.js` 就变一次；G1–G4 全跑一遍，且该批次**不适用 G6**（注释审计加不了覆盖面地板） |

**单次提交粒度**：一个缺陷（+判据+负对照）· 一个模块搬迁（+`INLINE_MODULES`+产物+文档）·
一条守卫拆分（+等价性证明+删旧）· 一个新目录（+权威文档+准入判据）·
**一个文件的注释批次**（+逐条处置结论）——**各自独立，不许合并**。

**禁止交叉**：§4 进行中改 `src/` 结构 · 同一次提交既搬 `src/` 又改判据 ·
停机重写守卫 · 把跨模块判据拆到单文件 · 借机加守散文的判据 · 新增映射清单而不给覆盖面地板 ·
**§2 注释审计与 `test/` 的重构期并行**（注释改一次就重建一次产物，而 **51** 处守卫提及读 `lib/client.js`
⇒ 红/绿无法归因；**两者之间二选一，做完一条再开另一条**）。
