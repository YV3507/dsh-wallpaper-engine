## 3. 顺序与策略

**明确不做**（都是本仓踩过的形状）：

- **不把字体集塞进 settings blob**：那会在 `config.json` 与 `fontsets/<id>.json` 之间造出**两个真源**，
  滑块一拖必有一份是旧的 —— 这正是 P1-5/P1-6 花两刀消掉的那类病。
- **不引入第二个共享内核**：字体集的键集与消毒规则**复用它**（见阶段 1），所以
  `verify-module-layout` ③ 的"共享内核白名单恰好 1 条"不动。
- **不引入 blob 下载**：导出走宿主响应头（见阶段 0 决策），客户端不新增 DOM 面，守卫不必为此加 mock。
- **不做"按未知版本猜"的静默兼容**：读不懂的版本要**拒绝并说明**，不许静默降级成"看起来正常"。

### 阶段 0：先决断言 + 两条决策（动手之前必须先有网）

(i) ✅ **持久化往返的网已落地** —— 落在**新建的** `test/verify-fontset.mjs`（而不是塞进既有的
`verify-theme-layer` / `verify-client`）：本项后面还有路径安全、迁移等价、导入导出三张网要挂，
同一族判据住一个文件比散在三个文件里更省。已入 `npm run verify` 链，判据为：
6 个字体键 → `serializeSettings` → 宿主 `sanitizeSettings` → **真 `PUT /settings`** → `config.json` → 读回 ⇒ 逐键相等；
两条负对照成对 —— ① 把某个字体键移出 `KINDS` ⇒ 该键在**客户端序列化与宿主消毒两侧**都消失
（钉住"静默丢弃"这条路，它同时是 `fontSetId` 的护栏）；② 复原后合法往返必须成功（否则①是恒真的空转）。
**牙齿实证**：临时把 `themeSize` 移出 `KINDS` ⇒ 恰好 4 条判据变红（键集 / 序列化白名单 / 负对照自身 /
往返），复原后全绿。

(ii) ✅ **迁移前外观 golden 已录**：四个纯计算载荷（颜色令牌 / 排版令牌 / 组件 CSS / DSL 钩子 CSS）
按 **DFS + 稳定序列 + 绝对锚点**展开成 42 行（形如 `colors.tokens.--dsw-alias-label-primary.light = "#112233"`），
逐行比对；负对照三条 —— 改一个输入值、**只挪一层**（值不变而锚点路径变深）、以及**判据自身的可达性探针**
（把 golden 上那个锚点改一位 ⇒ 比对必须立刻红，证明该锚点真的在被逐字比较）。
`--record` 只打印当前取值，供将来有意变更时重录（重录动作本身就是评审点）。

(iii) ✅ **两条决策已拍板**：

- **D1 字体值的真源归属 = 按 §9.5 的**字面**执行**：`config.json` 只留 `{ fontSetId, fontCustom }`，
  6 个字体键**退出 `KINDS`**，活动集的 6 个值由 `fontsets/<id>.json` 提供，`selection` 只做**运行期**载体。
  代价与必须一并处理的后果（不许留暗坑）：① 老 `config.json` 的内联值要**一次性迁移**成默认集，
  迁移判据就是 (ii) 的 golden；② 宿主不可达时的回落路径要重新定义（`localStorage` 缓存
  `serializeSettings` 只挑 `KINDS` 键 ⇒ 字体值会一起消失）—— 把"活动集正文"另存一个**独立缓存键**，
  而不是让它混进设置 blob；③ `test/fixtures/settings-sanitize-golden.json` 与
  `verify-client.mjs:1610-1654` 会随之改（这是**同交**项，不是顺手改）；④ 阶段 0 (i) 的键集判据会因此变红
  —— 那是设计中的信号，不是障碍：**它保证"6 个键退出 `KINDS`"这件事必须被显式处理**。
  *被否的备选*：字体集只当"命名快照库"、真源仍在 settings —— 拖一次滑块就让"集"与"实际外观"分叉，
  而分叉后"切换集"的语义无解（用户到底想扔掉还是保留这次微调？）。
- **D2 导出通道 = 宿主响应头**：`GET /fontsets/<id>/export` 带 `Content-Disposition: attachment`，
  客户端只放一个普通链接/导航（**复用宿主文件通道，不碰 blob**）。
  *被否的备选*：客户端 `Blob` + `createObjectURL` —— 那要给两个挂载台新增 mock 面，且是本仓第一次引入该 API。

### 阶段 1 ✅：共享内核 + 宿主通道（先做宿主侧，风险最低且判据最硬）

- ✅ **键集与消毒复用既有共享内核**：`lib/settings-schema.js` 增 `FONTSET_KEYS`（= 那 6 个键）与
  `sanitizeFontset(raw)`（复用 `readOne` 的逐 kind 分支）+ `FONTSET_SCHEMA_VERSION` /
  `FONTSET_SCHEMA_TAG` + `isFontSetId`（单段白名单 + 保留段）。**没有新建 `lib/**` 共享模块** ⇒ 白名单不动。
- ✅ **新 `lib/routes/fontsets.js`**（`registerFontsetsRoutes(webServer, c)`）：list / get / put / delete /
  activate / import / export **七个端点**（`activate` 是落地时补的：`fontSetId` 既然在根字段上，
  `PUT /settings` 就带不动它，切换活动集必须有自己的一条 —— 且它只肯切到读得懂的文件）。
  落地时的一个形态决定：它们是**一个 `prefix` 注册下的子路径分派**
  （与 `scene-serve` 同形），因此 ROUTE-INDEX 只多**一行**（31 → 32 条路由）—— "族"是按端点算的，
  不是按注册条数算的（账本 §7-6 已补这句口径）。
  id 白名单 `^[A-Za-z0-9_-]{1,64}$` + 保留段（`import` / `export` 不许当 id —— 它们是子资源路径）
  + 目录包含性（分隔符无关的 `relative`，口径同 `resolveUploadFile`）；目录走 `pluginDataDir()`（见 §1 第 3 条）。
- ✅ **写 config.json 只经既有串行化**：`fontSetId` 是 `config.json` 的**根字段**（不在 settings 键集里，
  因此 `PUT /settings` 碰不到它），读写都在 `lib/index.js`（`readFontSetId` / `setFontSetId`），
  写走 `enqueueConfigWrite` —— 与 settings / uploadDir 同一条队列。
- ✅ **一次性迁移**：读到"老形状"（6 个键内联、无 `fontSetId`）⇒ 生成 `fontsets/default.json` 并
  把活动 id 写回 config。**落地时改成了惰性迁移**（原计划暗示在启动期做）：`apply()` 会被**没有**
  `DSH_WE_DATA_DIR` 隔离的守卫调用（`verify-scene.mjs` 就是），那时 `pluginDataDir()` 指向用户真目录
  ⇒ 启动期写盘会污染真机。惰性版只在**第一次真的用到字体集**时写，由"`fontSetId` 是否为空"决定，
  天然幂等；判据里有一条**"`apply()` 一个字节都不写"**的断言把这条钉住。
  六个内联键**这一刀不摘**（客户端还没迁过来）—— 摘掉是阶段 2 的事，见下。

**验收（已全部满足）**：① 字体集文件的写-读往返逐键相等（含导出字节 → 导入读回）；
② 路径穿越负对照**逐条**（19 个非法 id 单元级 + 18 个非法请求行为级，后者断言**目录内容一个字节都没变**）
+ "合法 id 必须成功"（否则判据恒真）；③ 迁移等价 = 阶段 0 (ii) 的 golden（**直接接同一份**：
迁移后的值算出的外观必须与 golden 逐锚点相同，配"改一个值 ⇒ 立刻红"的配对项）；
④ `docs/ROUTE-INDEX.md` 重生成（31 → 32）+ `verify-route-index` 绿 + `lib/types/index.d.ts` 的路由条数同交。
守卫共 71 条判据全绿。

**这一刀有意留下的窗口（阶段 2 必须收口）**：此刻 `settings` 里的六个内联键与 `fontsets/default.json`
**同时存在**（前者仍是活路径的真源，后者是迁移快照）。阶段 2 把客户端改成读字体集时，必须：
① 把六个键移出 `KINDS`（**阶段 0 的 ① 判据会因此变红 —— 那是设计中的信号**）；
② 处理窗口期的分叉（用户若在这两刀之间改过字体，内联键比文件新 ⇒ 以**内联键**为准重写文件，

### 阶段 1b ✅：两层存储 + 随包预设（**需求变更后插入的一刀**，必须在阶段 2 之前）

**需求变更**：既要"随包就有少量可用预设"，又要能导入导出新预设，还要能人工切换。原设计只覆盖了
"用户层 + 导入导出"，"随包"是新的一层。**评估结论：路线不变** —— 单一真源（D1）、键集契约、
id 白名单、`$schema` 版本语义、导入导出形状全部照旧；变的只是**存储层从一层变两层**。

- ✅ **两层**：随包层 `lib/fontsets/<id>.json`（发布物、**只读**；解析照 `WEBWALLGL_DIR` 的先例
  `resolve(dirname(fileURLToPath(import.meta.url)), …)`）+ 用户层 `<pluginDataDir>/fontsets/`（可写）。
  同一 id **用户层胜**；列表带 `origin` / `overrides` / `broken` ⇒ 客户端不必自己猜"这份是谁的"。
- ✅ **D3 = 写时复制**：编辑随包预设 ⇒ 自动生成同名**用户层覆盖**（响应标 `overrides: true`），
  随包那份字节不动；`DELETE` 掉覆盖 ⇒ `restored: 'builtin'`，即**「恢复随包原样」**。
  随包预设本身**删不掉**（400）—— 发布物不是用户数据，而"删掉我的覆盖"是可判定的出路。
  *被否的备选*：只读 + 另存为（第一次改就多一步，且"改不了"的报错不如"改了看得见"）。
- ✅ **先落 1 份随包预设** `compact`（「紧凑」）：只收**标题梯级与小字梯级**，正文/表格保持官方值 ——
  是一条与 DSH 自己的全局字号不重叠、也踩不到可读性下限的轴。其余预设以后加文件即可。
  ⚠️ 随包 id **必须避开 `default`**（迁移产物占着这个名字；撞名会让那份随包预设被**永久遮住**）—— 守卫钉住。
- ✅ **切换的扩展位**：`activate` 定为**唯一改指针的写原语**；将来"按条件自动选预设"是**策略层**，
  必须调同一个原语落指针 —— 不允许再长出第二处"当前该用哪份"的判定。
- ✅ **包内只读是机器事实**：守卫断言"整个跑完后包内目录**逐字节**不变"（文件名 + 内容短哈希），
  并给快照函数配可达性探针（内容改一位 ⇒ 摘要必须变）；再加"随包预设逐份有效"（版本 / id 与文件名
  一致 / **没有值被 `sanitizeFontset` 悄悄丢掉** —— 随包数据是我们自己写的，一个 typo 会让所有人中招）
  与"随包预设必须真的改变外观"（空壳预设 = 用户切换了却没反应，配"全空 ⇒ 判它不改变外观"的配对项）。

**同交**：`package.json` 的 `files` 加 `lib/fontsets/`（`verify-package-files` P1 要求 `files` 覆盖
`lib/` 下**每一个**文件）；`docs/MODULE-LAYOUT.md` 登记"随包数据目录"这一形态。

### 阶段 2 ✅：客户端消费（**六个字体键退出 settings 持久化白名单**是承重的一步）

- ✅ **机制落点比计划的措辞更准**：那六个键**退出的是 settings 的持久化白名单**，而不是从 `KINDS`
  里删掉 —— `sanitizeFontset` 要按**同一份 kind** 消毒（一条路径，两处宽严不会分叉）。实现是
  `sanitizeFromSchema` / `serializeSettings` 里各一条 `if (FONTSET_KEYS.includes(key)) continue;`，

  设置 blob 里不该有"指针"这种东西。
- ✅ **宿主侧的迁移前护栏**（计划里没有、实现时发现必须补的一条）：字体值还没有自己的家时，

  ⇒ 采纳它并回 `adopted: true`。

⑥ `npm run verify:all` 全绿。

**验收后修复：点「字体自定义」白屏（真机反馈）**。根因不是字体集通道本身，而是**"键离开 settings blob 之后，
谁保证消费方同步拿得到它们"**：

1. 那六个键退出 settings 持久化白名单 ⇒ `readPersisted()`（→ `sanitizeSettings`）**不再提供**它们；
2. 唯一剩下的供应商是**异步**的 `loadFontSet()`（还可能失败）⇒ `selection` 里可以**根本没有** `themeColors` 等键；
3. 面板的配色区是 `sel.fontCustom && …` 门控的，且直接 `sel.themeColors[role.id]` —— 于是**打开总开关的那一刻**
   才第一次求值这一行 ⇒ `Cannot read properties of undefined (reading 'primary')` ⇒ React 渲染期抛 ⇒ 整个面板崩。
   （**已实测复现**，见判据 ⑧ 的配对项；修复前 `selection` 的初始化只摊平了缓存那一步，没缓存时就是 `{}`。）

**修法**（数据侧为主，边界为辅）：
· `fontset-store` 增 `fontValueDefaults()`（= `sanitizeFontset({})`，**全函数**：任何输入都给出六个形状可读的键）；
· `selection` 初始化按 **`readPersisted()` → `fontValueDefaults()` → `readCachedFontSetValues()`** 摊平
  （兜底必须在缓存之前；有缓存用缓存那份，没有就是兜底那份）；
· 令牌层那几个取值 getter 与订阅回调各补一道 `|| {}` / try（第二道：订阅回调跑在 `emit()` 里，抛出去就是"改一下设置整块面板崩"）；
· 判据 ⑦ 钉"初始化必须有兜底且排在缓存之前"（**牙齿实证**：删掉那一行 ⇒ 恰好一条判据变红）+ 兜底的全函数性；
  判据 ⑧ 直接渲染外观页签：**用客户端那份兜底值必须渲染得出**，配对项"缺 `themeColors` 必然抛"证明前者不是恒真。

**教训（写进计划 §5）**：把一个键从持久化白名单里搬走时，**异步载入不算供应商** ——
所有**同步读**它的消费方（面板渲染、订阅回调）必须在同一处拿到一份同步兜底，否则失败形态是"UI 崩"而不是"值不对"。

**如实记下的差额**（不假装已覆盖）："**点滑块 → PUT 到活动集**"这条**写路径的行为级**判据没有在本阶段落地 ——
本挂载台（`test/*-smoke.mjs` 用的假 React + mock DOM）驱动不了面板滑块的 `onChange`（`useState` 是空实现，
切不到「外观」页签），而 `selection` 对外不可见。现有覆盖是：静态契约（字体键不再经 `setSetting`、写入走
`setFontValues`、启动链顺序）+ 宿主侧接受 `{ values }` 这份体的行为判据（阶段 1 的 ⑤）。⇒ **阶段 3 补**。

### 真机反馈：「宿主返回 404 / 405」——**不是接线错，是宿主没重挂**

现象（2026-09-28）：面板里按「刷新」→ `字体集不可用：宿主返回 404`；按「新建」→ `宿主返回 405`。

查证过程（三条独立证据，互相印证）：

| 证据 | 结论 |
|---|---|
| `build-stamp.json` 记着**当前加载的宿主模块**的加载时刻与文件 mtime | 加载于 **20:07:13**（当时 `lib/index.js` mtime 19:48:58） |
| `lib/routes/fontsets.js` 的创建时间 / 阶段 1 提交时间 | 族文件 **20:35:08** 才诞生、注册在 **20:39:10** 提交 —— **晚了 28 分钟** |
| 插件自己的请求诊断 `diag/http.jsonl` 里 `fontsets` 命中数 | **0** —— 客户端的请求**根本没到本族**（本族每条请求都会经 `traceRequests` 落一行） |
| 两个错误文案的形状（`宿主返回 404` / `宿主返回 405`） | 本族每个非 2xx 都带 `{ error }` 信封 ⇒ **裸状态码一定来自别的层**（SPA 兜底：GET 未知路径 404、非 GET 405） |

根因：**宿主模块只在启动时 `load` 一次，而浏览器里的 bundle 是每次刷新重新取的**。于是
「刷新页面」换掉了前端，宿主进程里还是 20:07 那份 —— 前端新、宿主旧。**重启 DSH（不是刷新页面）**
后 `apply()` 重新注册即可。确认方法：`build-stamp.json` 的 `at` 必须晚于 `lib/index.js` 的 mtime。

同交（让这个失败模式下次自己说出来）：
- 通道内**所有**请求改走 `fsFetch` / `fsJson`（一律 `parse: 'always'`）—— 否则读不到宿主的 `{ error }`，
  面板上只剩一个状态码；
- 失败文案统一经 `fontSetFailureReason`：宿主给了 `{ error }` 就用它的原话，**裸 404/405** 翻译成
  「宿主里没有字体集路由（DSH 还是旧版本）：重启 DSH 后再试」（判据成对：带信封 ⇒ 原话照搬、不猜）。
- 教训（写进本文，因为它是**部署/开发流程**的事实而不是代码事实）：本守卫群里的路由判据都直接调
  `route.handler()`（或替身 fetch），**绕过 DSH 真正的路由匹配**，因此"宿主里有没有这条路由"这一层
  它们照不到 —— 能照到它的只有运行时事实（加载戳 / 诊断日志 / 文案形状）。
