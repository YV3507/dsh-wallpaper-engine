# ADR-0010: 玻璃可关性的再裁定与共存四态（glass off-revisit & coexistence modes）

- **Date**: 2026-10-09
- **Status**: Accepted
- **Deciders**: 用户（共存审计计划拍板）+ 实现（本仓）
- **Amends**: ADR-0008（Consequences 的「放弃：关闭某一面即回原生纯色」一条与触发线第一条）

## Context

ADR-0008 放弃「关闭某一面即回原生纯色」的理由是：那些面上还有一批**不挂门控**的令牌改写
（壁纸激活即生效），"关"得到的是半玻璃 ⇒ 要关得像样必须先让**令牌层**也能整组回退，
"复杂度远超收益"。它同时写下触发线：「若要把『恒挂』的门控属性改回可关：需要先让令牌层也能整组回退」。

2026-10-09 的共存审计（原始记录与分批计划：[`../wip/COEXISTENCE-AUDIT.md`](../wip/COEXISTENCE-AUDIT.md)）
对着那条触发线复算了令牌层，结论是**前提已经成立**：

- 不挂门控的 `--dsw-*` 声明只剩**封闭白名单**：`body[data-we-thinking-native]`
  （思考块**自己**的开关 —— 有名字、可关、语义正确）与 `.we-layer`（插件自有元素，卸载即消失）；
  其余全部挂在 `data-we-glass-*` 或 `data-we-wallpaper` 门控之下 —— **整组回退的结构已经存在**。
- 复算方式：`node test/tools/token-contract.mjs --stats`；真源 [`../TOKEN-CONTRACT.md`](../TOKEN-CONTRACT.md)
  （生成物，`test/verify-token-contract.mjs` 逐字节对账，并以**白名单封闭判据**钉住：
  新增任何一条无门控改写即报错）。
- 兼容性 harness 已经在**真的测**这条回退：`test/compat-harness-pages.mjs` 摘掉
  `body[data-we-glass-page]` 后断言各面退回原生实色。
- 唯一必须保留的共享责任 `--dsw-alias-bg-base: transparent`（壁纸要看得见，页面就必须透）
  已挂在壁纸门控下、归壁纸半边 —— 契约守卫钉住「bg-base 必须全部挂壁纸门控」。
- 同期确认的另两态：「关壁纸、留玻璃」今天已有守卫钉着（无壁纸时页面玻璃锚点仍须在）；
  「两边都关」的实现已存在于皮肤让路路径（`enterSkinYield` 一族），只是只认皮肤中心一个信号、
  不可被用户或第三方声明。

## Decision

**D1 — 修订 ADR-0008 的放弃结论。** 「关玻璃」从「不可行（令牌层回退复杂度远超收益）」改为
「**前置条件已成立，缺的是产品级主开关与一批守卫改写，不是架构**」。ADR-0008 正文保持原样
（它是历史）；其 Consequences 中该条按本 ADR 阅读，触发线里「若要把『恒挂』的门控属性改回可关」
一条视为**已满足**。

**D2 — 目标形态 = 一个模式键、四种共存态。** `full`（默认）/ `glass-only`（今天已支持的关壁纸）/
`wallpaper-only`（缺主开关，渲染层就绪）/ `off`（= 皮肤让路态，升格为用户与第三方可声明的状态）。
**不做两个独立布尔**：布尔组合会与既有门控属性的正交语义打架，且会产生组合爆炸。

**D3 — 实施按三批走，主开关最后。**
① **文档与契约**（本文 + `docs/COEXISTENCE.md` + `docs/TOKEN-CONTRACT.md` 与守卫 —— 已落地）；
② **协议与可见性**（属性级 opt-out、对外让路信号、自我属性守恒诊断、卸载健壮性）；
③ **主开关与守卫改写**（四态落地）。
理由：主开关是唯一会**大面积动守卫**的一步（恒挂断言、整页锚点断言、可读性形状锚都要逐条给新口径），
放在诊断与 opt-out 之后做 —— 受影响方先拿到自救路径，回滚面最小。

**D4 — 无门控白名单是封闭的。** 令牌契约守卫把无门控声明钉死在白名单内；
扩张白名单 = 一次可见的评审（改判据 + 生成物重算，随代码提交）。

## Consequences

- **收益**：玻璃第一次"关得掉"有了清晰路径；混搭问题从静默变成可诊断（契约 + 共存文档）；
  受影响方在主开关落地**之前**就已经有三步自查与（计划中的）属性级 opt-out。
- **代价**：四态落地要重谈一批守卫的口径 —— 清单与逐条现状见
  [`../wip/COEXISTENCE-AUDIT.md`](../wip/COEXISTENCE-AUDIT.md) §3.5；这些守卫钉的是当时的恒挂口径，
  改门前必须逐条给出新口径，这是真实的维护面成本（也是 ADR-0008 当年体感"复杂度远超收益"的真正来源）。
- **放弃**：① 两个独立布尔（玻璃开/关 × 壁纸开/关）的实现形态；② 「单面开关 = 该面回原生」的
  用户预期 —— 单面开关只退插件直接画的部分，令牌级配方随页面玻璃锚点走
  （用户口径写在 [`../COEXISTENCE.md`](../COEXISTENCE.md)）。

## 重新考虑的触发线

- 令牌契约的白名单需要**扩张** ⇒ 出现了新的无门控改写面，回来重看 D1 / D4。
- 宿主若提供**官方的令牌 opt-out / 主题协商接口** ⇒ D2 / D3 的属性级方案升级为走官方接口。
- 可读性契约若不再把声明钉在固定文本形状上 ⇒ ADR-0008 放弃的「按面变量间接层」可一并重开。
- 若皮肤让路态需要被第三方**主动协商**（而不只是我们让路）⇒ 重开 D2 的 `off` 态信号设计。
