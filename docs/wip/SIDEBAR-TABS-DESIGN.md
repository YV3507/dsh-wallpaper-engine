# 侧栏页签（壁纸 / 外观 / 播放）+ 类型筛选补「图片」—— UI 设计方案

> 状态：**已实现（2026-10-01），待真机视觉验收**。本文是这两项改动的唯一进度真源；
> 真机看过一遍、无返工后整体移入 `docs/archive/`（不就地改写成常青文档）。
> 已落地的东西与判据：见文末 §11；用户可见口径另见 `docs/CHANGELOG.md` 的「未发布」一节。
>
> 需求来源（用户口径）：
> ① 侧边栏「类型」下拉少了「图片」，补上；
> ② 设置 → 壁纸引擎的「外观」「播放」两页也要能在侧边栏快捷调 —— 目的是**调参数时能实时看到壁纸效果**
>（设置对话框占住屏幕中央一大片、且本身是雾化玻璃面，调「画面」类参数要判断真实观感就得反复开关设置；
> 侧栏只占右侧一窄条，调完即是所见）。
>
> 追加口径（同日确认）：声音组**在壁纸页保留**（播放页也有一份）；第一档标签用「壁纸」；
> 页签**记住**上次停的那页；侧栏改的状态**必须与设置页同源**（不许两边数据不一致）；
> 页签栏的位置在**「轮播」那一节下面** —— 上方的当前壁纸与轮播三档页签都显示。

## 0. 结论（先看这一段）

- **需求①**：`src/quick-panel.js` 的 `qpTypes()` 增加一档 `image`（`weT("图片")`，该键已在词表）。
  其余一律不动：仍是面板本地瞬态（`setTransient("qpType", …)`，不落盘、不影响设置页过滤与轮播候选）。
- **需求②**：侧栏（官方右栏 tab 与右滑抽屉两壳共用同一份 `QuickPanel`）在**「轮播」一节之下**加一条
  **三档页签**：**壁纸 / 外观 / 播放**。外观页 = 设置页「外观」的【主题】【细节】两节；播放页 = 设置页
  「播放」的【画面】节（去掉准备与诊断行）+【声音】节。**这些节与设置页共用同一批渲染器**（不是抄一份控件）。
  底栏那颗设置入口按钮**随当前页签换文案与落点**（深链到设置页的同名页签）。
- **需求④（同源）**：侧栏那几个页面**没有自己的状态** —— 所有改动走同一批处理器 / `setSetting` →
  同一份 `selection` store → 两个界面都从它渲染。两边同时开着时，改一边另一边**当场跟着变**（`emit()` 重渲染），
  设置页关着时下次打开读到的也是同一份值。见 §4.7。
- 主要工作量不在 UI，而在**把 12 个「外观 / 画面」处理器从 `WallpaperPicker` 组件闭包提升到模块级**
  （同当年播放控制处理器提升的那一刀；见 `src/quick-panel.js` 文件头）。
- 判据面：设置页形态必须**逐字不变**（surface 缺省 = 现状，配负对照）；需求① 那条「四档齐全」判据要扩成五档；
  另加"两面同源"与"侧栏零直写"两组判据。

### 1.1 为什么不能直接把设置页那两页塞进侧栏

1. **处理器拿不到**：`renderAppearanceTab` / `renderEffectsTab` 只从 `ctx` 取外界，而它们的 `ctx`
   由 `WallpaperPicker` 就地组装 —— 侧栏（另一个组件）组不出同一份 `ctx`，除非把那批处理器提升。
2. **有些行在侧栏没有意义**：出图来源 / 实时帧 / 自定义画面（文件选择）/ 帧率上限（触发抽帧转码）/
   源信息与转码进度 —— 统称**准备与诊断**，属于"这台机器怎么出图"，不是"现在看起来怎么样"。
3. **一处 CTA 会指错地方**：`renderEffectsTab` 的空态按钮走 `setTransient("pickerOpen", true)`
   —— 那是**设置页内部的库下钻**；侧栏里点了不会有任何可见反应。侧栏的空态应该是「去挑一张」
   （切到本面板的「壁纸」页）。

## 2. 方案总览

```
┌ 官方右栏 / 右滑抽屉（同一份 QuickPanel）────────────────────────┐
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ [封面] 当前壁纸标题 · 场景 · 播放中            [暂停][清除] │ │ ← 常驻
│  └──────────────────────────────────────────────────────────┘ │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 轮播：[— 选择轮播列表 — ▾]      [下一张]                   │ │ ← 常驻
│  │       自动轮播 ⌾   按所选列表定时切换                       │ │
│  └──────────────────────────────────────────────────────────┘ │
│  ┌─────────┬─────────┬─────────┐                              │
│  │  壁纸   │  外观   │  播放   │  ← 三档页签（复用 .we-tabs 视觉）│
│  └─────────┴─────────┴─────────┘                              │
│  ╔═══════════════ 当前页（此区独立滚动）══════════════════════╗ │
│  ║ 壁纸：壁纸列表（搜索 / 类型 / 列表·卡片）+ 声音组            ║ │
│  ║ 外观：主题（主题随壁纸 / 配色 / 玻璃颜色 / 玻璃透明度）      ║ │
│  ║       细节（雾化 / 边框）                                 ║ │
│  ║ 播放：画面（壁纸模糊 / 亮度 / 对比度 / 饱和度 / 壁纸透明度 / ║ │
│  ║             暗化 · 实时渲染组 · 倍速 · 适配 / 翻转）        ║ │
│  ║       声音（音量 / 壁纸音轨）                             ║ │
│  ╚══════════════════════════════════════════════════════════╝ │
│  [ 底栏（随页签）：壁纸引擎设置 › · 字体与更多外观 › · 更多播放设置 › ] │
└───────────────────────────────────────────────────────────────┘
```

四条结构性口径：

- **常驻区 = 当前壁纸 + 轮播 + 页签栏 + 底栏**，只有页签内容区滚 —— 直接对上宿主"tab 身体固定高、
  滚动自管"的契约；也保住现状的可用性（开侧栏第一眼永远是"现在放的是什么、能不能暂停"），
  同时让**换壁纸 / 开关轮播在三档页签下都够得着**（调外观 / 播放参数时想换一张对照很常见）。
- **页签记忆**：`localStorage` 键 `dsh-wallpaper-engine:qp-tab`，默认「壁纸」；只记 UI 状态，
  不进 `config.json`、不需要 sanitize（同 `QP_VIEW_KEY` / `PICKER_TAB_KEY` 的既有口径）。
  不做"每次打开都回壁纸页"（用户上次在哪调，下次多半还要接着调）。
- **两侧页签互不驱动**：侧栏页签与设置页页签各自记忆；唯一的联动是底栏那颗**单向深链**（见 §4.4）。
  这是"视图位置"不是"数据"—— 需求④ 管的是数据，见 §4.7。
- **零第二份状态**：侧栏三页**不新增任何设置字段**，也不在组件里复制一份值 —— 控件是受控组件，
  值一律从同一份 `selection` 读、写回也用设置页同一批处理器（§4.3 / §4.7）。

## 3. 需求①：侧栏类型筛选补「图片」

改动就一行位置：`qpTypes()` 增加 `{ id: "image", label: weT("图片") }`（`"图片"` 已在 `WE_I18N_EN`，
不新增词条）。配套四件事：

1. **位置**：**追加在末尾**（全部 / 场景 / 网页 / 视频 / 图片），不动现有四档的顺序 —— 现有用户的手感
   不变，「补一档」不该顺手重排。若更想要与设置页下拉一致（视频 / 网页 / 图片 / 场景），那是另一次
   有意的重排，不混在这次改里。
2. **宽度**：`.we-qp__viewbar .we-qp__type` 当前有 `max-width` 约束；新增一档后选项文字仍是两个字，
   不需要放宽。**不加计数**（设置页那一条带 `（n）`，侧栏这条保持窄形态；`.we-qp__viewbar` 本来就
   允许换行，但没必要为计数多占一行）。
3. **它筛的是什么**：宿主把上传目录里非 `mp4` 的单文件归为 `image`（`lib/index.js` 的上传扫描段），
   所以这一档主要是**用户自己上传的图片壁纸**；WE 工程目录是 scene / web，不落在这里。
   另外别忘了一个既有的叠加关系：侧栏列表 = `playableInventory()`（已按**设置页**的分级 / 类型过滤）
   再叠侧栏本地的 `qpType`（面板注释已写明）—— 若用户在设置页把类型档设成了"视频"，侧栏选「图片」
   会是空的，这是既有语义，不改。
4. **空态要说清原因**：已有「该类型下没有可播放的壁纸」这句话（`typeFilter !== "all"` 分支）。
   但侧栏列表是**两层过滤叠加**的（设置页的分级 / 类型档先筛，侧栏档再筛）—— 若列表为空而
   `selection.typeFilter !== "all"`，空态要追加一句把**上游那个档**点出来（「设置页的类型档当前是
   『视频』，切成『全部』才能看到图片」），否则用户会以为"没有图片壁纸"。
   这是需求④（两边一致）在筛选这条链上的落点：**不共享的是视图档，共享的是"为什么空"的解释权**。

**判据**：`test/verify-scene-live.mjs` 里那条「侧栏列表类型筛选：四档齐全 …」当前是
`[['all','全部'],['scene','场景'],['web','网页'],['video','视频']].every(…)` —— 加第五档**不会让它变红**
（它不是计数断言）。但这正是"新档位零覆盖"的形状，按本仓纪律要把它扩成五档并保留负对照，
改法写在 §8。

## 4. 需求②：侧栏三档页签

### 4.1 每页放什么（分档表）

| 侧栏页 | 内容 | 来源（与设置页共用同一个渲染器） |
|---|---|---|
| **壁纸** | 壁纸列表（搜索 + 类型 + 列表·卡片 + 快切）+ 声音组 | 现状的列表节原样；声音组改用 `renderAudioTab(ctx)` |
| **外观** | 主题（主题随壁纸 / 配色 / 玻璃颜色 / 玻璃透明度）+ 细节（雾化 / 边框） | `renderAppearanceTab(ctx)`，`ctx.surface === "sidebar"` |
| **播放** | 画面（6 滑块 + 实时渲染组 + 倍速 + 适配 / 翻转）+ 声音（音量 / 壁纸音轨） | `renderEffectsTab(ctx)` + `renderAudioTab(ctx)`，`ctx.surface === "sidebar"` |

**轮播那一节已提到常驻区**（在页签之上，三档都显示），所以壁纸页只剩列表与声音 —— 换壁纸 / 开关轮播
不必先切回壁纸页。

留**设置页独有**（侧栏不出现，靠底栏深链一跳）：外观的【全局字体】【输入光标】【窗口与侧栏】三节；
播放的【准备与诊断】行（出图来源 / 实时帧 / 自定义画面 / 帧率上限 / 源信息与转码进度）。

> 判据一句话：**凡"调一下就要看屏幕上的壁纸变成什么样"的行，进侧栏；凡"这台机器怎么出图、要不要转码、
> 状态是什么"的行，留设置页。**

### 4.2 常驻区与滚动

- 常驻四块：当前壁纸卡、轮播节、页签栏、底栏 —— 全部 `flex: 0 0 auto`（页签栏本身也是 `.we-tabs` 的
  既有 `flex: 0 0 auto`）；只有页签内容区 `flex: 1 1 auto; min-height: 0; overflow-y: auto`。
- **壁纸页保持它现有的形态**：内容区里是「列表」+「声音」，列表自带滚动、viewbar（搜索 / 类型 /
  列表·卡片）钉在列表上方，声音组在列表下方常驻（现状就是这样，不新增滚动层）。
- 外观 / 播放两页用内容区那一层滚，页面内部**不要再叠一层 `overflow`**（一页一个滚动条）。
- 抽屉态（`.we-repo-panel`，固定宽度 + flex 列）同一套规则，靠 `dock` 修饰类分叉，与现状一致。
- 官方档的宿主契约（tab 身体固定高 + `overflow:hidden`）继续由 `.we-qp--official` 的兜底滚 + 这里的
  分区滚动一起满足：**页签栏与常驻区任何情况下都不被滚走**。

### 4.3 渲染器复用（这一节是工作量所在）

**做法：给两个渲染器一个可选的 `ctx.surface`，侧栏档少画一部分；设置页档（缺省）逐字走现状。**

- `renderAppearanceTab(ctx)`：`surface === "sidebar"` 时跳过【全局字体】【输入光标】【窗口与侧栏】三节。
  主题 / 细节两节一行不改。
- `renderEffectsTab(ctx)`：`surface === "sidebar"` 时跳过【准备与诊断】那一组行；空态 CTA 改调
  `ctx.onPickWallpaper`（侧栏切到「壁纸」页），不再 `setTransient("pickerOpen", true)`。
  其余（画面 6 滑块、实时渲染组、倍速、适配 / 翻转）一行不改。
- **负对照与 golden**：`surface` 缺省必须**逐字等于现状**（DOM 的 class 序列、属性、文本都不变）——
  写一条判据：同一份 `sel` 下，缺省 `ctx` 与 `surface: "settings"` 渲染出的树完全相同，且与
  `surface: "sidebar"` **不同**（负对照要有牙）。这是本仓 `picker-modal` 草稿模式（`draft=false`
  逐字走普通分支）已经用过的判据形态。

**前提：把 12 个处理器从组件闭包提升到模块级**（否则侧栏组不出 ctx）：

- 外观 6 个：`onAccent` / `onGlassColor` / `onGlassAlpha` / `onBlur` / `onBorder` / `onToggleThemeFollow`
- 画面 6 个：`onWallpaperBlur` / `onWallpaperOpacity` / `onBackgroundBrightness` /
  `onBackgroundContrast` / `onBackgroundSaturate` / `onScrim`
- 它们的函数体只碰模块级的东西（`setSetting` / `emit` / `applyEffects` / `selection` / `clampNum` /
  `DEFAULTS` / `themeFollowOnWallpaper`）⇒ **逐字搬家**，不重写（同 `onTogglePlay` 那一批的先例，
  `src/quick-panel.js` 文件头已记着这条口径：两壳共用同一份实现）。
- 留在组件里的（侧栏档不渲染）：`fontSet` / `officialColorOf` / `onThemeSize` / `onThemeWeight` /
  `onThemeFamily` / `onThemeColor*` / `onComponent*` / `onCaretColor` / `onFontAdvanced` /
  `onFontResetAll` / `onToggleFontCustom` / `onRefreshFrame` / `onClearGpuFrame` /
  `onRecaptureGpuFrame` / `onCustomFrameFile` / `onClearCustomFrame`。
- **失败形态要响亮**：侧栏组装 ctx 时，这些"只属于设置页"的字段**不要留 `undefined`**（将来某次编辑
  把一行挪进侧栏档，会变成静默无反应）—— 传一个立刻抛错的占位（`（控件名）在侧栏档不可用`）。
  这与"漏传字段 = 当场 ReferenceError"是同一条纪律：响亮且可定位。
- 实时渲染开关 / 启动等待 / 帧率 / 倍速 / 适配 / 翻转这些行是**渲染器里的行内箭头**（`onClick: () =>
  { setSetting(…); emit(); }`），本来就写在 `panel-tabs.js` 里，不需要提升。

### 4.4 深链（底栏按钮随页签）

- 壁纸页 →「壁纸引擎设置 ›」：现状（打开设置对话框，落在它自己记住的页签）。
- 外观页 →「字体与更多外观 ›」：打开设置对话框并**落在设置页的「外观」页**。
- 播放页 →「更多播放设置 ›」：打开设置对话框并**落在设置页的「播放」页**。

机制（`src/sidebar-right.js` 的 `openSettingsSection` + `src/client.js` 的 `WallpaperPicker`）：

1. 侧栏先写一个**瞬态请求**（`setTransient("settingsTabRequest", "appearance" | "playback")`）再走现有的
   DOM 打开路径（**不改那条路径**：账号菜单 → 「设置」项 → 我们的 nav 行）。
2. `WallpaperPicker` 用一个 `useEffect` 消费它：请求存在且与 `activeTab` 不同 ⇒ 走**同一个 `switchTab`**
   （于是"清待确认、退出下钻、写 localStorage、关于页拉 star"这些既有副作用一处不落），然后清掉请求。
3. 请求**只在被消费时清**；自动打开失败（那条 6s 超时的诊断分支）要顺手清掉 —— 否则用户几分钟后自己
   打开设置，会莫名其妙被弹到外观页。

> 为什么不用"直接写 `PICKER_TAB_KEY` 再打开"：那只对**组件重新挂载**有效；设置对话框是否卸载由宿主决定，
> 挂在原地时 `useState` 初值不会重读。瞬态请求两条路都覆盖。

### 4.5 视觉口径（逐条）

1. 页签栏与设置页同款零件（`.we-tabs` / `.we-tabs__pill` / `.we-tabs__tab`），**胶囊位移动效不另写**
   （同一份 CSS，同一段时长/缓动）；宽度按页签数现算，三档等宽。
2. 三档标签：**壁纸 / 外观 / 播放**（与设置页的两个同名页签**逐字相同**，深链落点也对得上；
   第一档叫「壁纸」而不是「壁纸库」：侧栏这页是快切列表，没有库视图的批量 / 隐藏 / 下钻）。
3. 窄到官方右栏的最小宽度时：三个两字标签不折行、不截断；`当前壁纸` 卡按现状的 56×40 缩略图 + 省略号
   标题；滑块行的数值读数列宽固定（沿用 `.we-picker__value` 的既有口径），拖动时不跳版。
4. 配色 / 玻璃颜色两组色板（预设 + 「自定义」取色）在窄列里**换行到标签下一行**是预期形态
   （`.we-picker__ctl--wrap` 已有此行为），不要为了塞进一行去改色板尺寸。
5. 空态：没有启用壁纸时进「播放」页 = 一句话 +「去挑一张 ›」（切到壁纸页），**不出现**设置页的
   「选择壁纸」下钻按钮。
6. 声音：**壁纸页保留**（放在列表下方的位置，现状就在那儿），播放页也有一份 —— 两处**同一状态、
   同一处理器、同一份渲染器**（壁纸页那份从手写副本换成 `renderAudioTab(ctx)`），不构成"两个真相"。
7. 无壁纸 / 库还没加载完：页签栏照常可点（三页都能进），页内容给各自的空态（外观、播放页本来就是
   "不给滑块"的形态，见 `renderEffectsTab` 的空态分支）。

### 4.6 不做的事（非目标）

- 不把【系统】【关于】搬进侧栏（吉祥物预览、浏览方式、二维码在窄列里没有必要；侧栏只补用户点名的两页）。
- 不做侧栏 ↔ 设置页的**双向**页签同步（各记各的，只有底栏那条单向深链）。
- 不动壁纸页现有的搜索 / 类型 / 列表·卡片 / 快切语义，也不动设置页壁纸库的下钻与批量。
- 不为侧栏另做一套更紧凑的控件（滑块 / 开关 / 色板尺寸沿用现有 token）—— 先看真实观感再决定要不要压缩。

### 4.7 状态同步（需求④：两边数据一致）

**原则：侧栏不持有第二份状态。** 侧栏三页是同一份 `selection`（模块级单例）的另一扇窗：
`useStore()` 订阅的就是它，改动经三个既有入口（`setSetting` 设置 + 落盘 / `setFontValues` 字体值 /
`setTransient` 瞬态）写回去。**现状已可核实**：全插件客户端只有个位数的 `useState`，且全是视图状态
（重渲染 tick / 设置页页签 / 抽屉开合与位置 / 列表·卡片偏好）——**没有任何一处是某个设置值的本地副本**。
这就是"两边不会不一致"的结构性依据；本次新增的两页必须维持这个形状。

| 状态 | 真源 | 侧栏这一侧怎么读写 | 设置页 |
|---|---|---|---|
| 当前壁纸 / 播放态 / 音量 / 音轨 / 轮播列表与开关 | `selection`（经宿主持久化） | 现成的模块级处理器（`onTogglePlay` / `onVideoVolume` / `onToggleRotation` / `onGroupChange` / `onNextWallpaper` …）与 `applySelection` | 同一份值；`emit()` 后两边一起重渲染 |
| 外观：配色 / 玻璃颜色 / 玻璃透明度 / 雾化 / 边框 / 主题随壁纸 | 同上 | 本次提升到模块级的 6 个处理器 | 同上 |
| 画面：模糊 / 壁纸透明度 / 亮度 / 对比度 / 饱和度 / 暗化 | 同上 | 本次提升到模块级的 6 个处理器 | 同上 |
| 实时渲染开关 / 启动等待 / 帧率 / 倍速 / 适配 / 翻转 | 同上 | 渲染器里的行内 `setSetting`（与设置页逐字同一段） | 同上 |
| 侧栏页签、列表·卡片视图、搜索词、侧栏类型档 | **只属于侧栏视图**（`localStorage` / 瞬态） | 侧栏自己 | 不跟（设置页没有对应控件，见下） |

"结构上同源"仍要专门钉的理由：两边的**渲染入口**不同（设置页 `WallpaperPicker` 的 `renderActiveTab`，
侧栏 `QuickPanel`），一旦有人在侧栏这一侧写成 `selection.glassAlpha = …`、或自己 `useState` 存一份值，
就会分叉而且**不会报错**。所以：

1. **侧栏零直写**：所有写入走处理器 / `setSetting` —— `src/quick-panel.js` 文件头那条棘轮
   （"不得出现 `selection.X =` 字面直写"）对新增的两个页面同样生效，判据照旧只看直写形态。
2. **控件受控**：值来自 `useStore()` 的 `sel`，组件里不放副本。
3. **两面同屏验一次**：设置对话框停在外观 / 播放页，侧栏切到同名页，改任一边的滑块，另一边必须
   同步跟着走；反向同样（见 §7）。
4. **面板本地瞬态不算"不一致"**：搜索词 / 列表·卡片 / 侧栏类型档是**视图状态**，故意不落盘、不共享
   （设置页没有对应控件，不存在两边显示不同值的情形）。唯一要当心的是叠加关系 —— 设置页的类型档
   会先把候选筛一遍，处理办法见 §3 第 4 条的空态说明。

## 5. 备选与取舍

| 备选 | 为什么不采用 |
|---|---|
| **只加两个"跳到设置页该页签"的入口**（侧栏出按钮，参数打开对话框） | 不解决需求本身：设置对话框占屏，看不到「调完之后壁纸什么样」。可作为附赠（已并入 §4.4 的底栏深链），但不能单独成立 |
| **侧栏自写一份外观 / 播放控件**（像现在的「声音」组那样） | 两处控件必然漂移（现有「声音」组的提示语就已经和设置页不一样）；且本仓已有一条守卫口径"抽屉与官方侧栏共用同一份内容"，复制会把这个先例打开 |
| **侧栏页签直接镜像设置页全部五页** | 【系统】【关于】在窄列里收益低、维护面翻倍；用户只点了两页 |
| **做成"快捷设置"折叠区，不加页签** | 面板会变得很长：现在壁纸列表自己滚，再加近 20 行控件会把列表压成一条缝；页签是**结构性**解法 |
| **把设置页整页当组件挂进侧栏**（当年抽屉的老形态） | 已退役：抽屉从"装整份设置页"改成"装快捷面板"是一次有意的收敛，不该回退 |
