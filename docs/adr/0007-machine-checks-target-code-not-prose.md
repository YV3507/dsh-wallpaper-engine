# ADR-0007: 机器判据只针对代码与磁盘，不针对散文（Machine checks target code and disk, not prose）

- **Date**: 2026-10-01
- **Status**: Accepted
- **Deciders**: YV3507
- **Depends on**: [ADR-0006](./0006-comment-discipline-as-written-convention.md)（本文把它的边界落成可执行的判定程序）
- **Amends**: [ADR-0006](./0006-comment-discipline-as-written-convention.md) 的 `Implementation` 行（文档类守卫的物理下线**已执行**）

> 本文只回答一个问题：**一条机器判据该不该存在**。它给判定程序与两份清单，不给"哪些文件要守"的静态名册 ——
> 名册会随代码演进腐化，程序不会。

## Context

ADR-0006 定了方向（"读代码的守卫照留，读散文的守卫不加"），但那条边界**只写在散文里**，
于是它没能拦住三件实测发生的事：

1. **边界被"看起来像读代码"的判据绕过**。撤除之后仍有一批判据在断言**源码里的散文片段**，
   例如 `tabsSrc.includes('有能力头栅栏（网页壁纸走独立媒体源）')`、
   `modalSrc.includes('ESC 返回')`、`read('src/panel-tabs.js').includes(' 档 · ')`。
   它们形式上在读 `.js` 文件，实质上在守"那句话别被改写"——作者改一句面向用户的话就判红。

2. **一次判据把自己的钉子钉在了一个 bug 上**。`verify-scene-live` 曾断言
   `sidebarSrc.includes('/设置|Settings/i.test')`：被断言的正是那个**只在 zh/en 有效**的
   宿主 DOM 锚点（宿主语言是繁中 `設定`、或语言包追加第三种语言时，设置入口**静默失效**）。
   结果是 ADR-0006 说的失效形态以最直白的方式出现：**修 bug 会让守卫变红**，于是没人修。
   按本文的判定程序，这条判据的失败信号**无法转成可机械执行的动作**（它要求"保持原样"）。

3. **一次性清理的验收判据留了下来**。退役线里那条"状态行不再出现笔误「秡」"是 P0-4 的收口判据，
   修完即**恒真**；`docs/README.md` §写作纪律 5 明写"基线只许收紧，**删完清空即为零残留**"，
   但没人执行最后一步 —— 它从"防复发的资产"变成"占位的死判据"。

同时另有一类**被误伤**的判据需要豁免，否则本文会被理解成"凡是 `includes()` 中文就撤"：
`test/**` 里大量 `treeText.includes('选择壁纸')` 的判定对象是**渲染出来的 DOM 文本**
（假渲染树的输出），不是源码散文。作者改文案时**测试跟着改**是对的 —— 那是行为断言。

## Decision

**判据的判定对象只能是"代码""磁盘""生成物"与"程序运行结果"；不得是"作者怎么措辞"。**

加一条判据、或保留一条既有判据之前，按下面四问逐个过。**四问全过才留**：

1. **判定对象是机器事实，还是人的措辞？**
   措辞（注释/文档的句子、标签文案、H1、笔误）⇒ **不加**。
   机器事实 = 源码结构、磁盘枚举、生成物复算、运行时行为。
2. **失败信号能否转成"可机械执行的动作"？**
   要能一句话说清怎么修（"重算索引"/"在清单里加一行"/"合并回平铺"）。
   若答案是"把那句话改回来"⇒ 判据守的是编辑，**不加**。
3. **判据能否被"空壳"满足？**
   能（例：一份标题对、正文空的文档就能满足"H1 点名"）⇒ 它守的是形式而非实质，**不加**。
4. **判据里是否出现面向用户的文案字面量？**
   是 ⇒ 只有两种出路：改成**可译键**（经 `weT(...)` 读，由 `verify-i18n` 承担"进没进词表"），
   或**撤除**。`includes('某句中文')` 直接进判据 = 违反本条。

**豁免（第 4 问的例外）**：判定对象是**运行结果**时不适用第 1、4 问 ——
渲染树/面板文本的断言、`/关于` 页里"值还在不在"的断言都属于行为断言，**照留**。
区分办法：那段文字是**从被测代码跑出来的**，还是**从源码文件里读出来的**。

**保留清单**（各写"守的机制"，不是"守的文件"）：

- **生成物 ↔ 复算一致**：`verify-route-index`（索引由 `lib/**` 机械重算、逐字节比对）。
  它读的 `ROUTE-INDEX.md` 是**生成物**，不是散文 —— 这就是第 1 问的"机器事实"。
- **枚举面完整性**：`verify-module-layout` ⑧（每个 `test/tools/*.mjs` 与 `compat-*.mjs`
  必须在中英 `DEV-GUIDE` 里被点名）。它防的是"工具只对作者可见"这一实测问题
  （曾有 9 个工具只有 1 个被点名），失败动作是"加一行"。
- **磁盘计数门槛**：`verify-module-layout` ⑥（`src/` 子目录成员数 ≥ `SRC_DIR_MIN_MEMBERS`）。
  纯目录计数，无数值漂移风险（门槛的真源就在守卫里，文档只写符号）。
- **可译键在位**：`verify-i18n` 对"面向用户文案是否进了词表"的对账。

**撤除清单**（本次已执行；每条记"为什么它会拦编辑而不是防腐化"）：

| 位置 | 原判据 | 撤除理由（对应第几问） |
|---|---|---|
| `verify-scene-live` | `sidebarSrc.includes('/设置\|Settings/i.test')` | **第 2 问**：失败信号要求"保持原样"，而原样正是那个 locale bug。改断言机制（`isSettingsText` 存在 + 门控/排除/重入锁在位） |
| `verify-scene-live` | `modalSrc.includes('ESC 返回')` | 第 1/4 问：提示文案。ESC 机制**未失去覆盖** —— `verify-client` 有真派发 `Escape` + 非 Escape 负对照的**行为断言**，静态复制品是冗余 |
| `verify-retired-lines` | `状态行不再出现笔误「秡」` | 第 3 问 + 写作纪律 5：P0-4 收口后恒真，属"已死仍占位" |
| `verify-retired-lines` | `read('src/panel-tabs.js').includes(' 档 · ')` | 第 1/4 问：四字散文片段 |
| `verify-adapter` | `tabsSrc.includes('有能力头栅栏（…）')` 等三条状态行文案 | 第 1/4 问：改成**机制**断言"三分支且每支是 `weT(...)`"（已做变异测试：去掉任一支的 `weT(` 即判红） |
| `verify-adapter` | `tabsSrc.includes('「窗口失焦时暂停」只在原生浏览器目标下提供')` | 第 1/4 问：门控本身由 `blurPause && switchRow(weT(...))` 那条钉住，提示文案无需入判据 |
| `verify-adapter` | `tabsSrc.includes('适配目标')` | 第 1/4 问：保留代码半边（`ADAPTER_TARGET_VALUES.map(`） |
| `verify-module-layout` ⑥ 后半 | `src/` 子目录被常青文档 **H1** 点名 | 第 1/3 问：守标题措辞，且空壳文档即可满足 |

## Consequences

**收益**

- **判据不再站在修复的对立面**。撤掉那条 `includes('/设置|Settings/i.test')` 的同时，
  locale 缺陷被修成"候选集"锚点 —— 两类失效（判据钉 bug、锚点随 locale 静默失效）一起消失。
- **同类失效有一句话的判据可问**，不必每次重新辩论"这算不算读散文"（四问 + 豁免）。
- **"撤除"有了终点**：第 3 问把"空壳能满足"作为撤除理由，一次性清理的收口判据因此有了明确的下线时点。

**代价（我们放弃了什么）**

- **`src/` 子目录的"有没有自己的权威文档"不再有机器兜底**。
  将来有人建 `src/<新目录>/` 而不写文档，**不会变红** —— 只剩约定与评审。
  本 ADR 接受：该判据只能验"标题里有没有那个字符串"，空壳即可通过，所以它此前提供的
  是形式合规而非真实覆盖（当前全仓只有 `src/font/` 一个子目录，收益本就极小）。
- **改文案的自由换来了"文案腐化无人拦"**。例如状态行的三分支措辞现在只被"必须是 `weT(...)`"
  钉住；某天有人把三个分支写成同一句，**不会变红**。缓解是评审，不是加回判据。
- **四问仍是判断，不是算法**。第 1 问的边界（"机器事实"）需要人来划；本文给的是判据与例子，不是恒真式。

## 重新考虑的触发线

出现下列情况时回来重评，**而不是悄悄把散文判据加回去**：

- 某处文案腐化**重复发生且造成实际误导**，且评审两次都没拦住
  ⇒ 届时应考虑把该文案**改成数据驱动的键**（可译 + 可断言"键在位"），而不是断言那句话的字面量。
- 出现"**空壳文档通过**"被实际利用的案例（建了子目录、放一份标题对内容空的文档）
  ⇒ 那是第 3 问没被贯彻，应按第 3 问处理，而不是恢复 H1 判据。
- `src/` 子目录数量增长到"每簇都该有独立文档"成为常态 ⇒ 届时应考虑一条**极窄**的判据
  （例如"子目录内的入口文件头注释里必须出现该目录名"），并在本文记明为什么它比 H1 判据窄。
