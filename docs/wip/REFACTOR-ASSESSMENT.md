## 1. 决策（先结论）

**不做立刻的结构性大重构**：先做一轮「减重 + 加固」，再按已验证的接缝分批抽取。

三条依据：① 病灶是**体量集中 + 边界缺失**（两个门面文件仍占手写代码约 27%），不是逻辑纠缠；② 守卫是唯一的安全网，
大重写会先拆掉它，而缺陷率与回滚史说明"一次改对"不成立；③ 当前最高风险曾是**零 CI**，已先补掉。

**顺序**：`P0 加固 ✅` → `P1 单一真源 + 零耦合抽取 ✅` → `P2 按接缝分批`（P2-9/P2-10 ✅，P2-11 🟡）→ `P2-12 静态帧线整体移除 ✅`。
**并行功能轨道**：`F 字体系统大改`（F0/F1/F2 ✅，F3 ⬜）—— 它的数据模型建立在 P1-5 之上，故排在其后。

### 3.5 E：`apply(ctx)` 拆分的必要性评估

> 复算：`node test/tools/analyze-host-apply.mjs`。
> **结论：不整体重写** —— 先做三条前置，之后**按路由族拆、一次一族**。触发条件见 §7 第 6、7 条。

**为什么不现在拆**：① 没有具体病痛指向它（对比 P2-9：那时有 26 处裸 `fetch` 的具体隐患）；② 代价是 **22 个共享可变闭包状态**
—— 某个 `register*` 拿到**拷贝**而不是引用会**静默**出错（路由偶发 404 / 统计错乱，最难定位）；③ 宿主侧安全网比客户端薄；
④ 没有"必须现在做"的外部压力。

**三条前置**（已全部就绪）：① 路由索引 `docs/ROUTE-INDEX.md` + `verify-route-index.mjs`；② 三条零覆盖路由补真实行为断言；
③ 巨石闭包状态清单（`host-route-index.mjs --deps`）。
⚠️ 第 ③ 步顺带更正一个**误测**：早期把"到下一个同级声明的距离"当体量，量成 1,795 行；真值 **293 行 ≈ `apply` 的 15%** ⇒
`apply` 不是"几块大肉"，而是 **~30 个中等处理器 + 助手共享 24 个闭包状态** ⇒ **更支持按族拆**。

**每族的固定动作**：① 新建 `lib/routes/<族>.js`，导出 `register<族>Routes(webServer, c)`，族内共享的随族搬走；
② `apply` 里改成一次调用，**共享可变状态只以引用进 `c`，不做拷贝**；③ 重新生成 `docs/ROUTE-INDEX.md`；④ 该族的守卫必须先存在。
后续族：`inventory` → `upload` → `scene` → `media`；被多族复用的助手（`serveFile` / `handleSceneFiles`）留在 `apply` 里、以引用进各族 context。

### 9.1 官方令牌层（F0 实测结论 —— **实现必须继续满足**）

官方扩展面是客户端 Cordis 服务 `theme`（入口 `ctx.get("theme")`，`overrideTokens(source, {令牌:{light,dark}})`）；
presenter 把快照写进 `body` 内联样式 ⇒ 内联胜过主题样式表 ⇒ 不需要 `!important`、不用 DOM 选择器、
不碰白闪路径；同 source 再调 = **替换**该层。**F0/F1 已关闭**，实现收口在 `src/font/`（三个纯计算文件 +
唯一碰 DOM 的 `apply.js`）；通道分工 / 9 条不变量 / 扩展步骤见 [`docs/FONT-SYSTEM.md`](../FONT-SYSTEM.md)。

**F0 真机实测结论**（`V1–V10` 是**约束**，不是编年史）：

| # | 结论 | 对实现的影响 |
|---|---|---|
| V1 | 入口**只能是 `ctx.get("theme")`**：`ctx.theme` 裸访问抛错 | **不改 `inject`**（加进去会在服务缺失时 park 整个插件） |
| V2 | `ctx.get` 是**启动竞态**（同实例实测 3ms 可用 / 7ms 不可用） | 必须**延迟 + 轮询**；同步取一次就定论 = 真机静默失效 |
| V3 | 写入**即刻走 `body` 内联** | 免 `!important`、免 DOM 选择器、不碰白闪路径 |
| V4 | `dispose()` **干净还原**（内联摘净，计算值回落样式表） | `fontCustom` 关 = **真·回到原生** |
| V5 | 一层注册**一次**即可**随配色自动换值** | **不要**监听配色变化重注册 |
| V6 | 快照里**没有令牌表**（`active.tokens` = 0）而样式表里 `--dsw-*` / `--dsh-content-*` = **377** 条 | 令牌清单与取值的权威来源是**样式表扫描 + `getComputedStyle`** |
| V7 | body 上 23 个内联自定义属性里 **0 个 `--dsw-*`** | 「令牌走内联」此前并未发生 ⇒ 我们是**唯一**往 body 写 `--dsw-*` 的层 |
| V8 | 裸字符串**抛错**；未知令牌**不抛也不生效**；同 source 再调 = **替换** | 必须自己按 **377 条白名单**校验令牌名 —— 写错不报错，只静默无效 |
| V9 | `client-diag` 的 `detail` 两端各截断 **300 字符** | "把令牌清单写进 live 诊断日志"需另开通道或只记紧凑摘要 |
| V10 | `--dsw-alias-label-*` 共 **10** 个角色；排版类令牌 **184** 条 | 首期只做颜色是对的；F2 面对的是 184 条排版令牌 |

> 原始证据（探针代码、两套配色的 377 条取值、逐条实测表）是**本地未跟踪**的
> 本机未跟踪的取证脚本目录（不入库）与 `~/.dsh-wallpaper-engine/diag/http.jsonl`；需要时按那份记录复跑。


### 9.5 数据与文件（F3）

| 落点 | 内容 |
|---|---|
| `~/.dsh-wallpaper-engine/fontsets/<id>.json` | 字体集本体（可分享；带 `$schema` 版本，加载时按版本迁移） |
| `~/.dsh-wallpaper-engine/config.json` | **只记** `{ fontSetId, fontCustom }` |

**理由**：localStorage 只有 5MB；宿主白名单漏键会**静默丢弃**（= R4）；滑杆每次回调都同步写 settings 太重。
导入导出复用 `/upload` + 数据目录 + 文件选择器的现有基建（F3 因此依赖 P2-9）。

### 9.6 红线（违反即回归）

1. **白闪红线**：不得引入 `:has()` / 祖先相关选择器；作用域只用属性/类**直接命中**。
2. **令牌层不写 `!important`**；body 默认层维持现状（只在 body 上用）。
3. **不抢** `--dsh-content-font-size`（那是 DSH 自己的字号设置）。
4. **`.we-*` 插件自身面板默认不跟随**（否则用户会把设置面板调糊）。
5. **readability floor 必须保留**：颜色角色化后更容易调出不可读组合 ⇒ 面板对越界值给提示。
6. **令牌名漂移**：未知令牌**静默忽略**；面板对"当前 DSH 不存在的角色"**置灰**。
7. **回落通道**：`theme` 注入失败 ⇒ 回到 `/style` 注入路径（**保留双通道**，按能力探测）。
